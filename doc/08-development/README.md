# 开发与扩展

本章面向要修改 TeamTalk 的开发者。它说明代码在哪、哪些边界不能破坏，以及常见变更必须同步
修改哪些层。

## 开发前

1. 从[产品与领域](../02-product/README.md)确认功能归属与对象。
2. 从[系统架构](../03-architecture/README.md)确认所有者和数据流。
3. 从[仓库导览](repository-guide.md)定位模块。
4. 阅读[工程约束](engineering-rules.md)。
5. 按[变更指南](change-guides.md)列出协议、服务端、SDK、缓存、UI、测试和文档影响。
6. 调整框架或构建版本前，按[依赖维护](dependency-maintenance.md)核对配套关系、数据格式与最小验收。

## 完成标准

一个业务能力不是“界面出现按钮”就完成。至少需要：

- 服务端权限与状态不变量明确。
- SDK/协议能表达，错误语义稳定。
- 事件与本地缓存可以恢复。
- Desktop/Android 入口符合各自交互模型。
- 本地边界测试和真实部署验收覆盖风险。
- 权威文档与功能状态更新。

## 不接受的收尾方式

- 用 UI 假数据代替未实现后端。
- 为了让测试通过增加只被测试调用的生产开关。
- 在多个 README 复制同一份 RPC/事件表。
- 把“本轮修改”和临时故障经过写进架构正文。
- 成功响应后再异步执行决定业务是否有效的安全校验。
