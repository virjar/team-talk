# 企业文档

本文定义 TeamTalk 文档能力的产品边界、信息架构、权限模型和跨端交互。字段与 RPC 见
[领域模型](domain-model.md)和[RPC 参考](../10-reference/rpc-reference.md)。

## 1. 产品位置

文档是公司长期积累的资产，不是聊天附件、群公告或超长 Markdown 消息。一级导航至少包含会话、
通讯录、文档和设置；未来待办、日历、会议、邮件也应以自己的领域入口出现。

群聊与文档的关系是“讨论和引用”，不是“拥有和授权”：

- 删除或解散群聊不会删除企业文档；
- 用户退出某个群不应自动失去与该群无关的空间权限；
- 文档可以被多个部门、多个项目群共同讨论；
- 消息未来可以引用 `documentId`，但文档正文、权限和历史仍由文档域裁决。

## 2. 信息架构

```text
企业
└── 文档首页（企业资产入口）
    ├── 可访问空间
    ├── 最近访问
    ├── 最近创建
    └── 文档空间（权限根，可创建多个）
        ├── 空间概览
        ├── 个人授权
        ├── 部门授权（可选包含下级部门）
        └── 目录树
            ├── 文件夹
            │   └── 文档
            └── 文档
                ├── 当前 Markdown 快照
                └── 不可变修订历史
```

空间不是组织树的镜像，也不自动等于某个部门群。一个五十人的事业部可以共同拥有一个空间，同时
其中三个小组仍各自使用受管部门群；反过来，一个跨部门项目也可以创建与任何单一部门都不等价的
空间。组织结构负责人员归属，文档空间负责资产协作边界。

## 3. 权限模型

空间角色从低到高为：

| 角色 | 能力 |
|---|---|
| 查看者 | 查看空间、目录、当前正文和历史版本 |
| 编辑者 | 查看者能力 + 新建、修改、移动和删除目录/文档 |
| 管理员 | 编辑者能力 + 修改空间信息、管理授权 |
| 所有者 | 管理员能力 + 归档空间；创建者天然是所有者 |

授权主体有两类：用户和组织部门。部门授权可以只包含直属成员，也可以覆盖整棵下级部门树。一个人
命中多个授权时取最高角色；所有者身份不通过可删除的授权行表示。

权限在每次服务端调用时根据当前组织成员关系重新计算，不把部门成员复制进空间 ACL。员工调离部门
后立即失去由该部门带来的访问权；直接个人授权仍可保留。客户端缓存、打开的标签或旧正文都不是继续
访问的凭据。已归档部门和不存在的组织节点不参与授权；若组织父链存在环，当前直属部门事实可保留，
但该路径不贡献任何继承祖先授权。

当前版本以空间为最小授权边界。目录或单文档例外授权、外链分享、水印与下载控制属于后续能力；在
这些模型完成前，不在界面中伪造不可执行的权限开关。

## 4. 目录与文档

目录节点分为文件夹和文档，统一通过 `parentId` 组成无环树。服务端必须阻止把文件夹移动到自身或
后代、把节点放到其他空间，以及删除非空文件夹。文件夹图从根到最深文件夹最多 128 个节点，因此文档最多有
128 个文件夹祖先；创建和移动必须校验整个子树，不能让后代越界。节点名称和位置都使用
`expectedRevision` 防止多端静默覆盖。

目录列表和首页索引只读取持久化的有界摘要，不查询 Markdown 正文。打开文档时才读取完整 Markdown
当前快照，历史列表也只返回版本摘要；选择某个修订后再加载完整正文。这样空间增长到数百篇文档时，
进入首页、展开目录或查看最近列表都不会传输全部正文。

目录树按文件夹懒加载。客户端只请求根节点和用户实际展开的分支，并把已加载节点展平为 38dp 左右的
紧凑可见行；树中不展示摘要、版本或创建人，这些信息属于首页索引或文档详情。从首页打开深层文档时，
客户端使用服务端返回的 root 到 parent 祖先路径逐层加载并展开分支，不需要预加载整棵树。

每次创建或产生实际内容变化的保存都会形成完整、不可变的修订；完全相同的重复保存是幂等操作，
不会制造空版本。恢复旧版本等价于以旧内容创建一个新修订，不删除或重写历史。两个客户端基于同一
revision 保存时只能有一个成功；失败客户端必须保留本地草稿。客户端对每个标签独立记录本地编辑
世代：保存请求发出后继续输入、切换标签或关闭标签时，迟到响应只能更新其目标标签的服务端基线，
不能覆盖新草稿、复活已关闭标签或污染另一篇文档的历史面板。

## 5. Desktop 工作台

“文档”是一级菜单。进入后先显示资产首页，而不是自动打开第一个空间；首页包含可访问空间、最近访问
和最近创建。选择空间或最近文档后才进入空间工作区。两层页面都占用导航栏右侧的全部内容宽度，
不被会话的三栏布局限制：

```text
文档首页
┌──────┬────────────┬────────────────────────────────────┐
│ 一级 │ 空间索引   │ 最近访问 / 最近创建               │
│ 导航 │            │                                    │
└──────┴────────────┴────────────────────────────────────┘

空间工作区
┌──────┬────────────┬────────────────────────────────────┐
│ 一级 │ 紧凑目录树 │ 空间概览 / 文档标签 + 编辑预览画布 │
│ 导航 │ 约 276dp   │                                    │
└──────┴────────────┴────────────────────────────────────┘
```

空间列表不会作为工作区的永久一栏；进入空间后只保留当前空间的目录树。用户可以跨空间打开多个文档
标签，切换标签时必须同步切换空间和树上下文，不能出现左侧目录与右侧正文属于不同空间。返回首页或
切换空间不关闭标签，也不丢失未保存草稿；关闭脏标签必须确认。

文档画布使用无边框标题和独立格式工具栏。安全的富文本核心包括 H1-H6、粗体、斜体、删除线、行内
代码、链接、有序/无序与嵌套列表以及撤销/重做。引用、代码围栏和 GFM 表格是一等可视内容块，可在
同一篇文档内与普通正文混排编辑；代码块保留完整信息串、围栏风格和空白，表格保留列对齐与单元格
Markdown。未触碰的块逐字保留原始源码，任务清单、图片、原始 HTML 等尚未建模的扩展只在局部显示
源码卡片，不能再把整篇文档自动退化为纯文本。完整 Markdown 源码是用户主动选择的高级入口。
任意字体、字号、颜色和对齐在进入权威 Markdown 模型前不作为可保存能力展示。

连续写作、开会和跨文档对照需要更大画布，因此工作台可拉出为独立窗口。拉出后主窗口显示明确的承接
状态，独立窗口继续使用同一个 session-scoped 工作台状态；关闭独立窗口后可在主窗口继续，无需重新
加载标签或草稿。自动化测试通过独立 window id 操作该窗口。

## 6. Android 工作台

Android 底部导航提供独立“文档”入口。窄屏使用逐层页面：文档首页 → 空间目录树 → 编辑器；系统
返回和页面内返回遵守未保存保护。它共享首页索引、空间、ACL、目录、修订和 Markdown 语义，但不
复制 Desktop 的多栏尺寸或窗口行为。

## 7. 当前一致性边界

文档当前通过打开、保存和手动刷新拉取远端事实，尚未进入 LocalCache，也没有持久化变更事件。因此：

- 同一客户端的多标签和独立窗口共享内存草稿；
- 最近访问是用户维度的服务端事实，只在正文通过实时 ACL 校验并成功打开后更新；
- 最近创建表示“当前用户可访问空间中新创建的文档”，创建人和空间名称必须明确展示；
- 另一设备的修改不会实时推送，保存时由 revision 冲突兜底；
- 当前不是实时共同编辑，不提供光标、逐字符合并或 CRDT；
- 评论、全文搜索、离线编辑和细粒度 ACL 需要先设计事件、缓存与冲突恢复。

## 8. 破坏性迁移

旧实验模型把 Document 直接挂在群 `scope` 下。项目尚未发布，本次协议版本升级后直接启用
`document_spaces`、`document_space_grants`、`document_nodes`、`document_content_revisions` 和
`document_user_recents`，不保留双写或兼容转换。`document_nodes.excerpt` 是首页和目录的读取投影；
测试部署可清理旧文档测试数据。正式发布后必须改用版本化迁移和摘要回填，不能再依赖重建数据。
