# 企业文档

本文定义 TeamTalk 文档能力的产品边界、信息架构、权限模型和跨端交互。字段与 RPC 见
[领域模型](domain-model.md)和[RPC 参考](../10-reference/rpc-reference.md)。

## 1. 产品位置

文档是公司长期积累的资产，不是聊天附件、群公告或超长 Markdown 消息。一级导航至少包含会话、
通讯录、文档和设置；未来待办、日历、会议、邮件也应以自己的领域入口出现。

群聊与文档的关系是“讨论和引用”，不是“拥有和授权”：

- 删除或解散群聊不会删除企业文档；
- 用户退出某个群不应自动失去与该群无关的空间权限；
- 文档可以被多个部门、多个项目群共同讨论；
- 消息未来可以引用 `documentId`，但文档正文、权限和历史仍由文档域裁决。

## 2. 信息架构

```text
企业
└── 文档首页（企业资产入口）
    ├── 可访问空间
    ├── 最近访问
    ├── 最近创建
    └── 文档空间（权限根，可创建多个）
        ├── 空间概览
        ├── 资产归属与责任人
        ├── 个人授权
        ├── 部门授权（可选包含下级部门）
        └── 文档树
            ├── 文档（正文 + 子文档）
            │   ├── 当前 Markdown 快照
            │   ├── 不可变修订历史
            │   └── 子文档
            └── 文档（当前没有子文档，仍可继续新增）
```

空间不是组织树的镜像，也不自动等于某个部门群。一个五十人的事业部可以共同拥有一个空间，同时
其中三个小组仍各自使用受管部门群；反过来，一个跨部门项目也可以创建与任何单一部门都不等价的
空间。组织结构负责人员归属，文档空间负责资产协作边界。

## 3. 权限模型

空间角色从低到高为：

| 角色 | 能力 |
|---|---|
| 查看者 | 查看空间、文档树、当前正文和历史版本 |
| 编辑者 | 查看者能力 + 新建、修改、移动和删除文档树节点 |
| 管理员 | 编辑者能力 + 修改空间信息、管理授权 |
| 所有者 | 管理员能力 + 归档空间、交接资产归属；只由当前责任人获得 |

授权主体有两类：用户和组织部门。部门授权可以只包含直属成员，也可以覆盖整棵下级部门树。一个人
命中多个授权时取最高角色；所有者身份不通过可删除的授权行表示。服务端把角色先映射为类型化能力再裁决，未知角色、错误
权限根或不完整证据都失败关闭，业务代码不直接使用 wire 角色数字做大小比较。

空间还有四类必须分开的事实：

- `createdBy` 只记录不可变的创建来源，交接后也不改写；
- `ownerPrincipalType + ownerPrincipalId` 表示可转移的业务归属，主体可以是用户或活动组织节点；
- `stewardUid` 是当前承担管理与交接责任的活动普通用户，也是唯一获得隐式 Owner 的身份；
- `DocumentSpaceGrant` 只表示可删除的协作权限，不冒充资产归属或创建来源；
- `policyRevision` 是显式 ACL 的独立乐观锁版本，只有 grant 事实真实变化时才递增。

个人持有时，归属用户必须与责任人是同一人。组织持有时仍必须明确指定一名责任人；“该部门持有空间”本身
不向部门领导、直属成员或子部门成员授权，这些人仍需要显式部门 grant 或个人 grant。这样“资产算谁的”与“谁能看、能编辑”
不会因组织树变动而被意外绑定。

权限在每次服务端调用时根据当前组织成员关系重新计算，不把部门成员复制进空间 ACL。员工调离部门
后立即失去由该部门带来的访问权；直接个人授权仍可保留。客户端缓存、打开的标签或旧正文都不是继续
访问的凭据。已归档部门和不存在的组织节点不参与授权；若组织父链存在环，当前直属部门事实可保留，
但该路径不贡献任何继承祖先授权。

每次新增、修改或删除 grant 都提交客户端读取到的 `expectedPolicyRevision` 与稳定 `operationId`。服务端在
同一锁定事务内先识别 actor 作用域的不可变命令收据，再做活动身份、typed `MANAGE_POLICY`、目标主体和
policy CAS 校验；真实 grant 变化推进 `policyRevision`，no-op 保存收据但不推进。相同 ID 改写请求、或
未提交的旧 revision 跨过后续 mutation，均返回 `409`。精确重放只确认原副作用已提交，不重放旧 upsert/remove；
其 `DocumentPolicyMutationResult(spaceId, policyRevision, effectiveRole)` 始终投影锁内当前角色和版本，避免旧
ACK 在后续撤销、重授或归档后复活权限。

只有当前责任人可以交接空间。交接同时提交 `expectedCustodyRevision` 和客户端稳定的 `operationId`：前者防止陈旧离职或管理方案覆盖
更新的交接，后者让响应丢失后的同一请求只返回已提交事实而不重复变更。即使旧责任人因首次交接已失去权限，与原 actor、空间和请求指纹
完全相同的重试仍可收敛；复用 operationId 但改写请求，或用陈旧归属版本发起新交接，都返回 `409`。交接收据同时是不可变的归属审计记录。
如果新 operationId 指向的 owner 与 steward 都和锁内实时事实完全相同，服务端以 `400` 拒绝这次空交接且不占用 operationId；调用方可修正为真正的交接后复用该 ID。

组织节点仍持有活动空间时不能归档，必须先将这些空间显式交接给其他用户或组织。管理控制面可先按离职员工盘点其仍负责或个人持有的
全部活动 DocumentSpace，再以稳定 operationId、计划指纹 CAS 和不可变逐空间收据原子交给显式 owner/steward；即使旧 steward 已被 ban，
经验证的管理员仍能恢复责任链。执行同时撤销该员工跨全部空间的显式 USER grant，空资产计划也保存零条目审计收据。ban 本身仍只做紧急凭据
封禁，不隐式交接；当前也不会在停用、调岗时自动提升到父部门或猜测 leader，跨网盘、项目、监控的全域离职编排仍是后续能力。

当前版本以空间为最小授权边界。子树或单文档例外授权、外链分享、水印与下载控制属于后续能力；在
这些模型完成前，不在界面中伪造不可执行的权限开关。

## 4. 文档树

空间中只有文档一种业务节点，没有只承载层级而不承载内容的文件夹。每篇文档都有自己的 Markdown 正文和
修订历史，同时可以有零个或多个子文档：没有子文档时它是叶节点，有子文档时它既是可打开的文档，也是子树的
组织节点。上级文档的正文通常用来说明和综述其子文档。

所有文档通过 `parentId` 组成无环树。服务端必须阻止把文档移动到自身或后代、把节点放到其他空间，以及删除
仍有子文档的文档。从根到直接父文档最多包含 128 个祖先；创建和移动必须校验整个子树，不能让后代越界。
节点名称和位置都通过同一条可靠结构命令提交，并使用 `expectedRevision` 防止多端静默覆盖；正文保存只
更新 `DocumentContent`，不能顺带改名或绕过结构命令。

活动数据使用明确容量边界：每个归属主体（用户或组织节点）最多持有 128 个活动空间，每个空间最多包含 10,000 篇活动文档，
空间根级或任一父文档下最多有 512 篇直接子文档。归档空间和删除文档会释放对应容量；创建与跨父文档
移动在服务端聚合锁内判定最后一个槽，并发请求不能各自看到同一个空位。列表若发现绕过正式写路径形成的
越界历史数据会明确失败，不会静默截断为一棵看似完整的树。

文档树列表和首页索引只读取持久化的有界摘要，不查询 Markdown 正文。打开文档时才读取完整 Markdown
当前快照，历史列表也只返回版本摘要；选择某个修订后再加载完整正文。这样空间增长到数百篇文档时，
进入首页、展开文档分支或查看最近列表都不会传输全部正文。

文档树按子文档懒加载。客户端只请求根级文档和用户实际展开的分支，并把已加载节点展平为紧凑可见行：
Desktop 约 30–32dp，Android 保留约 44dp 的触控命中高度。一行只表示一篇文档，不使用文件夹大图标或卡片分类；点击标题打开正文，展开按钮只控制子文档，两个动作不得
互相偷换。树中不展示摘要、版本或创建人，这些信息属于首页索引或文档详情。从首页打开深层文档时，客户端使用服务端
返回的 root 到 parent 祖先文档路径逐层加载并展开分支，不需要预加载整棵树。

同一父文档下的节点统一按不可变 `(createdAt, nodeId)` 升序展示。`createdAt` 在首次创建时确定，重命名、
编辑正文和移动都不改写；`nodeId` 只用于打破同一毫秒创建的并列，因此服务端、LocalCache、重启恢复和
测试替身共享一个全序。当前产品不提供拖拽或手动排序，也不保存第二套可变 rank，更不为尚未出现的协同
排序需求引入 CRDT。节点移入新父级后仍按自己的原创建身份进入目标同级顺序。

同一空间的客户端树缓存必须以 `nodeId` 保持全局唯一，不能让展平阶段的 visited 集合任意选择旧/新位置。
不同父分支响应乱序时按节点 revision 仲裁：低 revision 不能驱逐较新的缓存位置；同 revision 却指向不同
父文档表示服务端投影矛盾，客户端必须拒绝该次发布并要求重新刷新，不能任意选择一个位置。
`hasChildren` 是由子成员关系派生的展开提示，不随父文档正文 revision 递增；较新的父分支若返回
`hasChildren=true`，必须废弃同一节点此前缓存的空子分支并收起旧展开态，使下一次展开重新拉取，不能让
旧的空结果永久遮蔽另一端新增的子文档。
收到完整 `Document` 路径事实后，客户端在发起任何新请求前先使捕获的旧父分支、缓存中发现的旧父分支和
权威新父分支的在途响应全部失效，并从错误分支淘汰该 nodeId；随后显式绑定原 spaceId 刷新新、旧父分支。
最终展开不仅校验祖先链，还必须确认目标文档实际出现在权威父分支。空间或标签已切换、实例已重开时，
迟到的成功或失败都不得发布；当前路径发生矛盾时只把该实例降为未解析，不清除正文。

每次创建或标题、Markdown 正文发生实际变化都会形成完整、不可变的内容修订；标题只能通过可靠
`moveNode` 结构命令改变，`updateDocument` 是 content-only 保存。两条写路径竞争同一个节点 revision，
客户端需要改名并保存正文时先确认结构命令，再以返回的新 revision 提交正文。完全相同的重复保存是
幂等操作，不会推进节点聚合 revision，也不会制造空版本。只改变 `parentId` 的移动会推进节点聚合
revision，但不会复制一份正文修订，因此内容历史中的 revision 允许不连续；父级、标题和正文仍共同
竞争同一个节点 revision。服务端先校验 `expectedRevision` 再识别 no-op，所以携带陈旧版本的“结果看似
相同”请求仍然冲突。恢复旧版本等价于以旧内容创建一个新修订，不删除或重写历史。两个客户端基于同一
revision 写入时只能有一个成功；失败客户端必须保留本地草稿。客户端对每个标签独立记录本地编辑
世代：保存请求发出后继续输入、切换标签或关闭标签时，迟到响应只能更新其目标标签的服务端基线，
不能覆盖新草稿、复活已关闭标签或污染另一篇文档的历史面板。

手动刷新若从服务器得到明确 404，干净标签直接关闭；含本地修改的标签进入显式“原文档已删除”状态。
它仍可离线编辑，但旧 `documentId` 的保存、移动、历史与删除全部禁用，不能把 404 降格成普通路径未解析
而反复更新幽灵资源。用户选择“另存为新文档”后，客户端生成新的稳定 UUID，以当前空间根作为已验证
落点，把完整标题/正文和创建命令先持久化，再用该 UUID 幂等创建；原草稿恢复身份只在创建成功并完成
本机收尾后封存，失败或断网时继续保留可重试的新建草稿。

已保存且没有本地修改的文档可从“更多”菜单选择“移动到…”。目标选择器复用当前懒加载树，支持空间
顶层，并可继续展开分支查找数百篇页面；自身、当前父页面和客户端已知后代不可选，服务端仍对完整子树
做最终无环与深度校验。移动请求同步捕获标签实例、revision、旧父页面和目标父页面，并在首个 RPC 前
持久化稳定 `operationId + issuedAt` 与完整请求；成功后才更新标签路径并刷新旧/新分支，可重试失败则
显示“位置或名称变更等待确认”并由后台复用原命令。跨父级移动只对干净标签开放，脏草稿必须先保存，
不提供拖拽或自定义排序。
移动可能使同空间其他已打开页面的祖先路径失效，但客户端不得按标签总数无界并发拉取。路径校验由
session 级 latest-wins 批次统一拥有，按 `spaceId + documentId` 去重且同时最多发出 4 个请求；更新批次会
废弃旧批次的全部发布权，断网、超时或认证失效则在当前有界批次结束后停止。未完成校验的页面保持
`pathResolved=false`，之后由显式标签导航重新校验，不能用迟到结果覆盖已导航或重新打开的标签实例。

保存遇到 revision 冲突时，传输层返回稳定 `409`，客户端保持草稿并读取最新服务器快照。用户必须明确
选择“采用服务器版本”或“保留我的内容、基于最新 revision 继续”；后一选择本身不写服务器，仍需再次
保存。冲突快照按标签实例与本地编辑世代隔离，读取期间继续输入或切换标签时，迟到响应不得覆盖新状态。

一次保存若同时包含标题重命名与正文修改，客户端先把完整正文草稿持久化，再提交可靠结构命令。结构命令
离线排队或进程重启后，恢复流程只确认标题、父级和 revision，不把正文草稿伪装成已经随结构命令提交；
草稿继续保持 dirty，待结构命令收敛后由用户再次保存正文。当前没有“结构 ACK 自动触发正文 CAS”的隐式
第二次写入。

## 5. Desktop 工作台

“文档”是一级菜单。进入后先显示资产首页，而不是自动打开第一个空间；首页包含可访问空间、最近访问
和最近创建。选择空间或最近文档后才进入空间工作区。两层页面都占用导航栏右侧的全部内容宽度，
不被会话的三栏布局限制：

```text
文档首页
┌──────┬────────────┬────────────────────────────────────┐
│ 一级 │ 空间索引   │ 最近访问 / 最近创建               │
│ 导航 │            │                                    │
└──────┴────────────┴────────────────────────────────────┘

空间工作区
┌──────┬────────────┬────────────────────────────────────┐
│ 一级 │ 紧凑文档树 │ 空间概览 / 文档标签 + 编辑预览画布 │
│ 导航 │ 约 276dp   │                                    │
└──────┴────────────┴────────────────────────────────────┘
```

空间列表不会作为工作区的永久一栏；进入空间后只保留当前空间的文档树。用户可以跨空间打开多个文档
标签，切换标签时必须同步切换空间和树上下文，不能出现左侧文档树与右侧正文属于不同空间。返回首页或
切换空间不关闭标签，也不丢失未保存草稿；关闭脏标签必须确认。

文档画布使用无边框标题和独立格式工具栏。安全的富文本核心包括 H1-H6、粗体、斜体、删除线、行内
代码、链接、有序/无序与嵌套列表以及撤销/重做。引用、代码围栏和 GFM 表格是一等可视内容块，可在
同一篇文档内与普通正文混排编辑；代码块保留完整信息串、围栏风格和空白，表格保留列对齐与单元格
Markdown。表格以最后聚焦的单元格作为结构操作锚点：新增行插在当前行下方，新增列插在当前列右侧，
删除作用于当前行或当前列；表头行不能删除，且表格始终至少保留一列。未聚焦任何单元格时，新增操作
沿用末尾追加的惯例。可视表格最多 32 列、1000 个单元格（含表头）；新增行列会越界时入口禁用并说明
命中的上限，避免编辑后保存失败或重开退化为源码。未触碰的块逐字保留原始源码，任务清单、图片、
原始 HTML 等尚未建模的扩展只在局部显示源码卡片，不能再把整篇文档自动退化为纯文本。完整 Markdown
源码是用户主动选择的高级入口。
任意字体、字号、颜色和对齐在进入权威 Markdown 模型前不作为可保存能力展示。

连续写作、开会和跨文档对照需要更大画布，因此工作台可拉出为独立窗口。拉出后主窗口显示明确的承接
状态，独立窗口继续使用同一个 session-scoped 工作台状态；关闭独立窗口后可在主窗口继续，无需重新
加载标签或草稿。自动化测试通过独立 window id 操作该窗口。

## 6. Android 工作台

Android 底部导航提供独立“文档”入口，并以平台能力显式启用单文档前台模式，而不是按窗口宽度推断：
手机和平板都使用“文档首页 → 空间文档树 → 编辑器”的逐层页面，不展示多标签栏；Desktop 即使缩窄
窗口仍保留多标签契约。编辑器只保留空间标题栏的一个“返回文档树”入口。返回、打开另一篇或新建之前
必须同步捕获编辑器最后一拍正文，不能只读可能落后一帧的标签状态；干净文档直接关闭，未保存文档与
新建草稿必须确认放弃，取消后草稿继续保留。关闭后文档树仍定位到原文档的直接父文档（根级文档则定位到空间根）；从首页最近项异步
打开正文时，活动文档到达后直接进入编辑器。Android 共享首页索引、空间、ACL、文档树、修订和 Markdown
语义，但不复制 Desktop 的多栏尺寸、标签与窗口行为。
移动端确认放弃后，后续打开、切换或退出必须等待草稿取消 tombstone 成功且旧标签已经移除；不能先启动
目标导航，再由迟到的关闭动作推进导航世代并撤销该目标。
若保存请求仍在途，关闭接口必须返回明确的 `BLOCKED_BY_SAVE`，确认框继续显示“正在保存”并保留目标
操作；不能先关确认框再静默丢弃离开、切换或关闭意图。持久化取消失败同样保留原标签并允许重试。

## 7. 当前一致性边界

服务端仍是文档共享事实与访问权限的权威来源。客户端把最近一次成功读取的空间工作集、首页两类索引、
已展开的直接子分支和干净正文写入 deployment + dataset + uid 隔离的 LocalCache SQLite 投影。空间、
首页和分支都有独立的持久快照标记，因此“已经确认为空”和“从未加载”是两种状态；正文同时保留
root 到直接父文档的祖先路径。该投影用于断网读取，不是继续访问服务端的凭据，也不是整库副本。

未保存工作仍由独立的 `DraftStore` 续写层负责。它保存未保存/新建中的标签、稳定 ID 创建命令和待确认
破坏性操作，不与可重建的干净 LocalCache 投影混写。因此：

- 有持久账号时，断网冷启动仍可进入应用和文档工作台并显示离线状态。工作台先发布本机草稿和已缓存的
  空间/首页，选择空间、展开分支或打开正文时也先发布对应缓存，再在后台请求服务器收敛；已缓存的干净
  正文可离线打开，开始修改后成为 `DraftStore` 管理的本地未保存事实。未加载过或已被容量淘汰的分支、
  正文仍显示明确的“尚未缓存”，不能用空目录、空正文或旧 ACL 猜测伪装成功；
- 干净投影有硬边界：空间工作集最多 1,024 个身份，最近访问和最近创建各 50 项，直接子分支最多
  512 个节点，合计最多 20,000 个分支和 50,000 个节点；正文按最近使用顺序最多保留 512 篇且合计
  64 MiB UTF-8。空间分页工作集的容量淘汰只缩减空间索引，不等于撤权，也不会连带删除仍在独立预算内
  的正文和分支；正文 LRU 淘汰只表示下次离线打开可能命中缓存缺口；
- 网络、超时和服务端 5xx 不清除已经发布的干净投影。涉及空间、首页、分支或正文的成功 RPC 通过
  对应请求 lease 写穿 LocalCache，较晚的权威写入、删除、移动和新请求会阻止旧响应复活过时位置；
- 服务端明确返回 403 时清理该空间的空间索引、首页项、全部分支和正文，并同步退休界面的树、授权与
  远端身份；根分支 404 同样是空间终态。子分支 404 只清理对应父文档及本地已知子树，不误删整个空间；
  单个不可变修订 404 不能反推出活动文档已删除。上述终态仍保留未保存草稿为显式本地孤儿，旧远端身份
  不再可保存、移动、读取历史或删除；
- 远端明确删除但本机仍有修改的草稿会持久保存 `remoteMissing` 事实；重启和再次断网不能把它误还原成可更新的旧文档，只能继续编辑、放弃或另存为新的稳定创建命令；
- Desktop 可恢复多个脏标签，Android 产品界面仍只保留一个前台文档；二者都在远端空间列表重新成为权威后，以原稳定资源 ID 自动重试未确认的创建命令；
- move/rename 使用 LocalCache 内独立、最多 256 条且每个节点单槽的 durable outbox。网络、超时、408、
  429 或 5xx 保留首次冻结的 parent/name/revision/operationId/issuedAt 并跨进程重放；服务端首次成功返回当前
  `DocumentMoveResult`，精确重放只以相同 operationId 确认已提交。后一种空投影 ACK 必须先用缓存或一次
  当前 `getDocument/getNodePathSpine` 使本地位置、名称和 revision 收敛，临时读取失败继续保留命令，不能
  因 ACK 到达就先清 outbox；
- 空间创建返回 `DocumentSpaceCreateResult(spaceId, space?)`。首次创建或精确重放时，若空间仍活动且创建者
  仍是当前 steward，`space` 是包含当前 owner/custodyRevision 的实时投影；若创建者后来不再是 steward 或空间已归档，
  `space = null` 仍确认原创建完成。客户端先持久完成该创建 outbox，再清理干净空间投影并退休界面中的
  旧远端身份；不得把 null 当失败循环重试，也不得按原创建事实复活 Owner。若调用者仍有显式 grant，
  只能由后续 `listSpaces` 按实时权限重建实际角色；未保存内容按独立 DraftStore 的撤权孤儿规则保留；
- 工作台热状态按正文 `String` 的 UTF-16 code unit 计量，常态最多驻留 800 万字符，并为当前活动编辑器固定预留一份最大服务端基线和一份最大本地草稿（共 200 万字符）。dirty、creating 和活动标签不可驱逐；达到边界时只按打开顺序淘汰最早的干净非活动标签，重新打开时先尝试 LocalCache 正文，命中缺口才读取服务器。已经驻留的目标标签始终先发布本地正文再后台刷新，普通断网不能用加载失败清掉它。旧版本持久化的超常草稿只进入恢复债务区：保留全部未保存正文、清掉干净缓存且禁止借机增加身份；绝对上限由下述 32 MiB 持久记录总量再加一个活动编辑器预留推导，保存或关闭草稿后自动回到常态预算；
- 每个标签和创建命令独立保存，原子小清单只保存记录索引、活动标签和空间提示，不把全部正文聚合成一个巨大 JSON；持久化的 parent/ancestor 仅供稳定创建命令匹配，恢复时所有标签一律为 `pathResolved=false`，也不恢复选中父页面。路径必须由一份完整 `Document` 投影重新建立，可以来自 LocalCache 正文或新的服务器响应，不能只信任草稿清单。续写层同时以单记录 16 MiB、全部记录 32 MiB、最多 1024 个恢复身份约束内存与磁盘。恢复会在读取正文前先校验全部记录的精确聚合字节数。读取暂时失败必须保持可重试，并在成功恢复前阻止新操作覆盖旧数据；
- 明确放弃草稿或待创建空间时，客户端先持久化单调取消标记，再移除界面状态。即使随后的清单写入失败或进程退出，旧记录也不能复活或再次发送；
- 归档空间和删除叶文档在联网发送前持久保存稳定 operationId。结果未知时空间/文档保持只读并在恢复连接或重启后用同一 ID 重试；服务端确认后，本机先同时封存操作世代与受影响草稿，并从所有父分支及自身懒加载分支立即淘汰已删除 nodeId，再把目录重拉作为 best-effort 投影修复。明确业务拒绝只取消该操作世代，正文草稿继续保留；
- 归属交接返回不含 `myRole` 的专用 `DocumentCustodyTransferResult`，表示该命令实际提交的 owner/steward/custodyRevision，而不冒充当前空间访问快照。收据的精确重放始终返回原命令结果，即使空间后来再次交接或归档也不改写。SDK 在命令成功后立即尝试清理该空间的干净权威投影，由下一次 `listSpaces` 基于实时 grant 重建；普通本地清理异常只进入诊断，不得把已提交回执改写成可重试失败。未保存工作仍按独立 DraftStore 规则保留。当前尚无图形化交接工作流或自动恢复 outbox，调用方必须自行保存并在未知结果时复用同一 operationId；
- ACL 变更在进程内保存一个有界待确认命令身份。同一空间结果未知时，相同语义重试即使本地目录已刷新到
  更高 `policyRevision`，仍复用首次的 expected revision 与 operationId；不同 ACL 意图不得并发生成第二个
  命令。成功结果为 `effectiveRole = NONE` 时立即清理该空间全部干净投影并退休界面；仍可访问时更新角色与
  `policyRevision`，管理员再重拉 grant 快照。未保存草稿仍由独立 DraftStore 保留；当前 ACL outbox 不跨进程恢复；
- 最近访问是用户维度的服务端事实：创建文档时与文档、首个修订原子写入创建者记录，后续只在正文通过实时 ACL 校验并成功打开后更新时间。每个用户最多保留 1,000 篇最新访问记录，首页单次最多返回 50 篇；这个工作集不是完整访问历史；
- 最近创建表示“当前用户可访问空间中新创建的文档”，不区分叶节点和有子文档的内节点；创建人和空间名称必须明确展示。两个首页 SQL 都只做有界候选预筛，服务端还会为候选批量读取空间、grant 和组织归属快照，并由 `DocumentAuthorizationPolicy` 以 typed `DocumentCapability.READ` 最终裁决；它们不是文档搜索，当前仍无文档搜索能力；
- 所有者空间配额只约束一个归属主体持有的活动空间，不能把 128 的 owner 配额解释为用户可访问空间的全局结果上限。`listSpaces` 使用默认 32、最大 64 条的稳定不透明游标分页；每一页仍在同一读快照中以 129 行探针核对 actor 个人持有的 owner 配额，不能把损坏的超额事实拆成多个看似合法的页。客户端按需“加载更多”，并把远端空间、本机草稿空间和已打开空间合并到最多 1,024 个身份的有界工作集。远端窗口满后继续翻页会淘汰最早且未被选中/打开的远端空间，不会停在固定前缀；只有受保护的本机身份挤满容量时才暂停。刷新第一页时“不在本页”不等于撤权：当前选中和已打开的空间会保留，直到该空间的实时 ACL 查询给出明确业务拒绝；
- 当前没有 document Notify。进入工作台、选择/展开、打开正文、手动刷新、成功写操作，以及工作台打开后
  的每次断线重认证边沿会触发有界 RPC 收敛；仅停留在页面时，另一设备的修改不会实时推送，保存仍由
  revision 冲突兜底；
- 当前不是实时共同编辑，不提供光标、逐字符合并或 CRDT；
- 评论、全文搜索、全空间预取式离线镜像和细粒度 ACL 仍需先设计事件、缓存、权限撤销与冲突恢复。

## 8. 数据基线

文档域的当前基线由 `document_spaces`、`document_space_grants`、`document_space_custody_transfers`、
`document_node_move_commands`、`document_nodes`、
`document_content_revisions` 和 `document_user_recents` 组成，不保留群 scope 双写或兼容转换。
`document_nodes` 中的每个活动节点都是可打开、可修订的文档，`excerpt` 是首页和文档树的读取投影；
同级顺序直接由 `created_at, node_id` 推导，不另存 position。当前开发部署切换不兼容 schema 时直接重建
测试数据；正式发布后必须改用版本化迁移和摘要回填。
