# 产品定位

TeamTalk 是一个可私有化的组织内部即时通讯基础产品。它同时提供可用客户端、服务端、SDK 和
部署工具，目标是让中小组织以较低的开发与运维成本拥有自己的通信系统，并能继续扩展办公协作
能力。

## 服务对象

- 需要私有数据边界的中小组织。
- 希望在自有业务中嵌入 IM 能力的开发团队。
- 需要无头客户端、机器人或 AI 员工接入的自动化场景。
- 希望使用单一 Kotlin 技术栈维护服务端和多端客户端的团队。

## 产品原则

### 沟通域与企业资产域并列

消息、联系人、群和会话构成沟通域；文档空间与待办构成独立办公对象。文档按空间授权，待办由创建者与
执行人管理，可显式向关联群成员共享；群文件则由所属群的当前成员权限约束。群聊中的讨论与引用
不会自动授予原对象的访问权。协作能力只有在身份、权限、
生命周期和跨端入口完整后才进入产品，不为填满界面预造演示功能。

### 服务端拥有远端事实，客户端拥有交互状态

成员资格、消息序列、附件存在性、权限和已读水位由服务端裁决。草稿、焦点、窗口、下载进度等
局部体验由客户端管理。客户端可以乐观展示发送状态，但不能绕过服务端契约制造“成功消息”。

### 私有化是默认部署模型

所有附件都走 TeamTalk 自身端点；消息保存附件相对路径。HTTP URL 只是在客户端边界上根据部署
配置解析出的访问形式，不把第三方文件服务写入消息模型。

### 多端一致不等于多端界面相同

Android 与 iOS 使用触控和页面栈；Desktop 使用三栏、抽屉、弹窗和任务窗口。三端共享业务能力和视觉
语言，但不共享导航模型。

## 当前边界

- 面向中国大陆用户，客户端使用中文，当前不做国际化；Android 系统推送采用国内手机厂商官方服务，
  不接入 Google/FCM。私有发行的包名、签名与推送应用按部署方独立配置。
- 单组织、单体、单机优先，目标规模不超过万级用户。
- 不提供端到端加密；部署方控制服务端和数据。
- 不以海量公共群、跨组织联邦或全球多活为当前目标。
- 当前处于开发者预览阶段，具体版本见[功能状态](../10-reference/feature-status.md)；普通升级保留资料，同一协议 major 的已发行契约冻结，破坏性变更按[版本与迁移规则](../04-protocol/versioning.md)单独说明。
- 无头客户端提供 CLI、Agent 与有界授权的 MCP 接入；模型路由、RAG 和完整 AI 员工治理尚未实现。

## 核心用户旅程

1. 用户注册或使用持久 token 自动登录。
2. 添加好友或接受申请。
3. 发起私聊，或从联系人资料发起群聊。
4. 发送富文本与媒体；在多个设备上同步会话、未读和已读水位。
5. 搜索联系人、消息和文件入口。
6. 管理个人资料、群成员、邀请和登录设备。
7. 从独立“文档”入口加入企业空间，在紧凑文档树中同时打开和编辑多个文档；任一文档都可继续组织子文档。
8. 从待办工作台或群卡片处理任务，关联文档与附件，跟踪周期任务、延期和完成情况。
