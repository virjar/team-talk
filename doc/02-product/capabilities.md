# 能力模型

## 1. 身份与访问

| 能力 | 用户结果 | 核心约束 |
|---|---|---|
| 注册与密码登录 | 建立用户和设备会话 | 用户名/密码双端校验；错误文案防用户枚举 |
| 自动登录 | 重启后直接恢复主界面 | 持久化设备级稳定 refresh；每次认证轮换 access 并推进设备 epoch |
| 多设备 | 同一用户多端在线 | 设备独立 token；重复设备登录有明确替换策略 |
| 设备管理 | 查看和踢除设备 | 服务端推进设备 credential epoch、失效凭据并在提交后关闭旧连接 |

认证失败属于用户层终止事件，客户端应停止重连并回到登录流程；普通网络断开只重建连接层。

## 2. 联系人与发现

- 本地通讯录按显示名、用户名和备注搜索。
- 全局搜索统一承载联系人、消息、文件和服务发现。
- “添加好友”从搜索到的用户资料发起，不堆在通讯录标题栏。
- 好友申请是通讯录中的稳定入口，即使没有红点也可发现。
- 从用户资料可以发送消息，未来也可把该用户作为初始成员发起群聊。

## 3. 组织架构与部门群

- 一个部署实例承载一个组织根节点，目录必须保持单根无环树；根深度为 1，最多 64 层，
  活动节点硬上限为 10,000。二叉层级约 14 层即可覆盖该节点预算，64 层保留了充足业务余量，
  又能防止损坏单链无界消耗数据库与进程栈。
- 用户可以属于多个部门，并指定唯一主部门与职位。
- 单用户最多归属 32 个部门，单部门最多 10,000 名直属成员，整个组织最多 100,000 条直接归属关系；
  超限写入整体失败，客户端不得把分页上限误作截断后的权威目录。
- 活动与已归档节点共最多保留 20,000 个永久身份，部门群正/负投影共最多 20,000 条。归档行和
  负投影是防止旧任务复活权限的持久围栏，当前不自动回收；预发布阶段耗尽时必须显式重置测试数据，
  不能用隐式 TTL 或静默截断绕过。
- Desktop 和 Android 通讯录都把“组织架构”与“好友”作为并列视图；点击组织成员进入统一资料页。
- 任意部门可启用受管部门群，成员等于该部门子树中的全部用户。
- 部门移动、人员归属、负责人和机器人授权变化会幂等同步群成员；普通用户不能手工改变受管群成员。
- 部门群的子树用户、负责人和已授权机器人共同占用 1,000 个活跃成员名额。期望集合超限时组织事实
  仍保留，但群投影保持待收敛且拒绝访问；管理员缩小成员或机器人集合并发布新 revision 后自动恢复。

组织架构写入只开放给 `/api/admin/organization/**` HTTP 管理控制面，普通客户端读取固定使用长连接上的
强类型二进制 `OrganizationRpc`，避免终端绕过管理规则修改公司目录，也避免把核心终端读模型退化为
JSON/HTTP。

Desktop 与 Android 先展示按账号持久化的组织投影：冷启动尚未有快照、服务端权威空目录和更高 revision
已使旧非空行过期是三种不同状态。旧行可以继续离线浏览，但不作为搜索、文档或其他资产权限的裁决
依据。在线管理写提交后会向已经就绪的连接发送瞬时 revision 提示；断线提示不补发，每次认证恢复都
通过 revision 绑定的全量二进制 RPC 对账兜底。

## 4. 私聊与群聊

私聊关注快速建立和一对一已读语义。群聊在同一消息模型上增加成员、角色、群公告、邀请链接、
禁言和退出/解散等管理能力。

每个群最多有 1,000 个活跃成员。群主从创建时即占一个名额，普通用户、机器人和系统服务身份使用
同一预算；退出或移除会释放名额，历史非活跃成员重新加入仍需要重新占用名额。满员只返回固定的
容量错误，不展示内部人数或目标成员状态。

Desktop 的群设置属于当前聊天上下文，从右侧滑入覆盖式检查器；Android 使用全屏页面栈。群名
只承担识别，不作为隐藏入口。

### 保存的消息

用户可将已有消息收藏为自己的独立副本，并在 Android 与 Desktop 查看。首次收藏前不占会话列表；
收藏后作为普通会话参与排序，不强制置顶。进入后可以继续发送文字和文件，复用现有消息、附件、
搜索与多设备同步能力。

这是系统提供的个人私有会话（`ChatType.SAVED`），并非普通好友或可登录的系统用户：只有本人是成员，
没有对端 `peerUid`，书签角标表达系统服务身份，不伪造用户 UID 或普通用户资料页。

## 5. 消息与富媒体

文本默认走富文本消息：编辑器提供多行、Markdown 快捷格式、代码、链接和 `@` 提及。消息显示
支持回复、转发、编辑和撤回。

媒体遵循统一附件模型：

- 图片可预览和进入画廊。
- 语音在应用内播放。
- 视频先经当前认证会话完整下载并原子发布到账号隔离缓存，播放器只读取本地文件；缓存命中时不依赖
  服务端带宽或在线状态。
- 小文件可以静默下载；大文件由用户点击下载，并在气泡中显示进度动画。

消息只有在服务端完成权限、内容与附件存在性校验后才能返回成功 ACK。SDK 的前置校验改善错误
反馈，但不能代替服务端安全裁决。

## 6. 会话与未读

- 会话按置顶和最后消息时间排序。
- 草稿属于当前用户当前设备的交互状态，切换会话时保存并在列表提示。
- `readSeq` 只增不减；服务端计算未读并同步给同一用户的其他设备。
- 对端已读是成员水位的派生展示，不把每条消息写成独立布尔状态。

## 7. 搜索

客户端顶部提供全局搜索入口。服务端使用 Lucene 与中文分词索引消息，关系数据仍由 PostgreSQL
查询。搜索结果进入原业务上下文：用户结果打开资料；消息结果携带 `chatId + serverSeq` 打开会话，
目标不在驻留窗口时有界加载对应历史，随后精确滚动并短时高亮。无权限、已撤回或不存在的目标以
不泄露授权状态的统一结果安全降级。

## 8. 文件

文件上传使用 HTTP，成功响应返回规范化相对路径和客户端可用 URL。消息只保存相对路径；发送时
服务端查询 FileStore，确认文件存在、元数据匹配且发送者有权使用。下载始终经 TeamTalk HTTP
端点并携带当前 access token；上传者或引用该文件的会话当前成员才能读取，不接受任意第三方 URL。

群共享文件在同一 FileStore 上建立独立逻辑空间。群成员可以创建目录、发布文件、追加不可变版本、
重命名和删除；每次修改使用 revision 防止并发覆盖，历史版本参与群配额，活动条目、同级子条目和
单文件版本另有固定硬上限，零字节对象也占基数槽，操作写入基础审计记录。创建目录、发布文件、追加版本、
重命名和删除都使用稳定命令标识；客户端在首个 RPC 前把完整规范载荷写入
deployment + dataset + uid 隔离的 SQLite outbox，网络未知结果和进程重启都复用原
`entryId/commandId` 重放。队列最多 256 条、单条最多 24 KiB、合计最多 3 MiB，超限拒绝新操作而不驱逐
已保存的未知结果。暂时失败会告知用户操作已保存；后台最终 ACK 或确定拒绝后，页面只收敛受影响的目录、
文件版本或已打开路径。
聊天附件不会自动变成群文件。持久 `GROUP_FILE_CHANGED` 事件会使客户端本地目录投影失效并刷新，
打开页面、操作完成和手动刷新也能对账；离线目录读取已有本地投影，搜索与完整历史治理仍未完成。

## 9. 企业文档

文档是与会话、通讯录并列的一级能力。用户进入自己有权访问的空间，在紧凑文档树中创建和编辑 Markdown
文档、查看完整修订历史并把旧版本恢复为新修订。文档可以同时承载正文和子文档，上级文档不是独立的文件夹。空间可以向
用户或部门授权查看、编辑和管理角色；
部门成员变化会立即改变有效权限，群聊不参与裁决。
创建来源、可转移的用户/组织归属、唯一人类责任人和协作 grant 是四类独立事实；组织持有不会自动给其成员授权。
归属交接使用独立版本和稳定 operationId 防止并发覆盖与重复执行；组织节点仍持有活动空间时不能归档。

Desktop 支持跨空间多标签与独立大窗口，Android 使用空间、文档树、编辑器的窄屏分层。每次保存携带
`expectedRevision`，服务端拒绝静默覆盖。当前协作方式仍是“共享版本 + 冲突检测”，不包含实时光标、
逐字符合并、评论或 CRDT。已缓存正文可以离线续写并持久保留本机草稿，联网后保存；
没有读过的正文不能离线打开。图形化资产交接、离职自动编排与文档搜索也尚未完成。详细产品结构见[企业文档](documents.md)。

## 10. 自动化通知

当前群成员可以从群设置创建通知机器人，系统把它显式授权到当前普通群或部门群，再由 CI、监控、
审批等系统通过已绑定目标群的 HTTP URL 发送 Markdown。调用正文不再携带群 ID；成功发送同时满足：
凭据有效、机器人启用、URL 中的群在白名单、服务身份仍是成员、消息通过正常 MessageService 校验。
需要自动重试的业务可以通过可选 `Idempotency-Key` Header 去重。

机器人 token 只对创建者显示一次且不可恢复。创建者可以轮换或移除自己的机器人；群主和群管理员
可以从本群移除由群成员创建的任意机器人，但不能查看或轮换其他创建者的 token。由系统管理员下发的
机器人只在后台治理。该入口只解决外部系统主动通知；可靠的事件订阅、回调重试和双向应用仍属于后续应用平台。

群成员创建、外部系统调用与凭据处置见[通知机器人接入](../05-clients/notification-bots.md)。

## 11. 管理与运维

- 管理后台提供用户查询、封禁和基础实例管理。
- `/health` 汇总 PostgreSQL、RocksDB、Lucene、FileStore 和 TCP 状态。
- 服务端连接日志只按定向 DIAGNOSTIC 策略有界启用，并可与客户端遥测事件精确联查；客户端 fault/crash 经 HTTP 上传。
- 构建产物嵌入 commit 与 build time，用于定位实际运行版本。

## 12. 跨端原则

共享的是领域能力、SDK、视觉令牌和可复用内容组件；不共享的是窗口模型、导航、输入法和系统
集成。任何新能力都应先定义领域结果和服务端契约，再分别设计 Desktop 与 Android 的承载方式。
