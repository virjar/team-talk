# 能力模型

## 1. 身份与访问

| 能力 | 用户结果 | 核心约束 |
|---|---|---|
| 注册与密码登录 | 建立用户和设备会话 | 用户名/密码双端校验；错误文案防用户枚举 |
| 自动登录 | 重启后直接恢复主界面 | refresh token 持久化并一次性轮换 |
| 多设备 | 同一用户多端在线 | 设备独立 token；重复设备登录有明确替换策略 |
| 设备管理 | 查看和踢除设备 | 服务端删除 token 并关闭目标连接 |

认证失败属于用户层终止事件，客户端应停止重连并回到登录流程；普通网络断开只重建连接层。

## 2. 联系人与发现

- 本地通讯录按显示名、用户名和备注搜索。
- 全局搜索统一承载联系人、消息、文件和服务发现。
- “添加好友”从搜索到的用户资料发起，不堆在通讯录标题栏。
- 好友申请是通讯录中的稳定入口，即使没有红点也可发现。
- 从用户资料可以发送消息，未来也可把该用户作为初始成员发起群聊。

## 3. 组织架构与部门群

- 一个部署实例承载一个组织根节点，部门可以无限分级但必须保持无环树。
- 用户可以属于多个部门，并指定唯一主部门与职位。
- Desktop 和 Android 通讯录都把“组织架构”与“好友”作为并列视图；点击组织成员进入统一资料页。
- 任意部门可启用受管部门群，成员等于该部门子树中的全部用户。
- 部门移动、人员归属、负责人和机器人授权变化会幂等同步群成员；普通用户不能手工改变受管群成员。

组织架构写入只开放给管理端，普通客户端使用只读 RPC，避免终端绕过管理规则修改公司目录。

## 4. 私聊与群聊

私聊关注快速建立和一对一已读语义。群聊在同一消息模型上增加成员、角色、群公告、邀请链接、
禁言和退出/解散等管理能力。

Desktop 的群设置属于当前聊天上下文，从右侧滑入覆盖式检查器；Android 使用全屏页面栈。群名
只承担识别，不作为隐藏入口。

## 5. 消息与富媒体

文本默认走富文本消息：编辑器提供多行、Markdown 快捷格式、代码、链接和 `@` 提及。消息显示
支持回复、转发、编辑和撤回。

媒体遵循统一附件模型：

- 图片可预览和进入画廊。
- 语音在应用内播放。
- 视频按需下载或流式播放。
- 小文件可以静默下载；大文件由用户点击下载，并在气泡中显示进度动画。

消息只有在服务端完成权限、内容与附件存在性校验后才能返回成功 ACK。SDK 的前置校验改善错误
反馈，但不能代替服务端安全裁决。

## 6. 会话与未读

- 会话按置顶和最后消息时间排序。
- 草稿属于当前用户当前设备的交互状态，切换会话时保存并在列表提示。
- `readSeq` 只增不减；服务端计算未读并同步给同一用户的其他设备。
- 对端已读是成员水位的派生展示，不把每条消息写成独立布尔状态。

## 7. 搜索

客户端顶部提供全局搜索入口。服务端使用 Lucene 与中文分词索引消息，关系数据仍由 PostgreSQL
查询。搜索结果进入原业务上下文：用户结果打开资料，消息结果打开会话；精确滚动到消息序列仍是
独立能力。

## 8. 文件

文件上传使用 HTTP，成功响应返回规范化相对路径和客户端可用 URL。消息只保存相对路径；发送时
服务端查询 FileStore，确认文件存在、元数据匹配且发送者有权使用。下载始终经 TeamTalk HTTP
端点并携带当前 access token；上传者或引用该文件的会话当前成员才能读取，不接受任意第三方 URL。

群共享文件在同一 FileStore 上建立独立逻辑空间。群成员可以创建目录、发布文件、追加不可变版本、
重命名和删除；每次修改使用 revision 防止并发覆盖，历史版本参与群配额，操作写入基础审计记录。
聊天附件不会自动变成群文件。客户端 v1 在打开页面和修改后主动刷新；实时变更事件、离线索引、搜索
和保留回收仍是后续能力。

## 9. 自动化通知

管理员可以创建通知机器人，把它显式授权到普通群或部门群，再由 CI、监控、审批等系统通过 HTTP
发送 Markdown。成功发送同时满足：凭据有效、机器人启用、群在白名单、服务身份仍是成员、消息
通过正常 MessageService 校验。业务侧必须提供幂等键。

机器人 token 只显示一次且不可恢复；轮换会立即让旧 token 失效，停用会撤销全部授权并把机器人移出
群。该入口只解决外部系统主动通知；可靠的事件订阅、回调重试和双向应用仍属于后续应用平台。

## 10. 管理与运维

- 管理后台提供用户查询、封禁和基础实例管理。
- `/health` 汇总 PostgreSQL、RocksDB、Lucene、FileStore 和 TCP 状态。
- 服务端连接日志使用采样 trace，客户端 fault/crash 经 HTTP 上传。
- 构建产物嵌入 commit 与 build time，用于定位实际运行版本。

## 11. 跨端原则

共享的是领域能力、SDK、视觉令牌和可复用内容组件；不共享的是窗口模型、导航、输入法和系统
集成。任何新能力都应先定义领域结果和服务端契约，再分别设计 Desktop 与 Android 的承载方式。
