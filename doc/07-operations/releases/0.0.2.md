# TeamTalk 0.0.2

TeamTalk 0.0.2 补齐协作 basics：@ 提及、任务、文档评论与统一内容搜索，富草稿跨设备同步，
并改善双端媒体与日常聊天体验。本版继续作为开发者预览发布，普通升级保留已有服务端资料和
客户端安装数据。

## 日常使用

- @ 提及全链路：会话与文档编辑器内输入 @ 弹出光标处补全（键盘上下选择、Enter 确认、原子 Token），
  长按/右键头像快捷 @ 该成员；被 @ 的会话在列表显示「@我」红点，已读水位推进后清除。
- 消息体验：私聊我方消息逐条显示 ✓（送达）/ ✓✓（已读）；向上翻历史时底部浮现「有新消息」
  胶囊一键回底；续体消息对齐、撤回后头像恢复；群头像改为成员头像拼图。
- 任务协作：任务创建、指派、状态流转与审计；任务以卡片消息（TASK_REF）分享进会话；到期提醒。
- 文档协作：文档评论（列表、回复、编辑、删除）；文档可直接分享到任意会话；管理员可开启
  文档空间一键导出 markdown zip；文档图片区块网格化并接入全屏画廊。
- 统一内容搜索：文档、群文件与聊天附件按关键词与文件类型搜索，结果分页。
- 富草稿：含图片/文件的草稿与上传意图持久化，进程重启或断电后恢复；READY 草稿跨设备同步。
- Android：应用内检查更新与系统下载器升级；相机拍摄视频直接发送；国内厂商后台推送
  （小米/华为/荣耀/OPPO/vivo/魅族）；刘海屏顶部适配。
- Desktop：macOS 原生全屏下画廊改为主窗口内全幅 overlay（修复 EDT 卡死）；会话列表宽度与
  输入区高度可拖拽调节并记忆；右键消息上下文菜单。

## 可靠性与运维

- 服务端增加管理安全（管理员凭据与操作审计）与管理台系统设置页；管理路由按域拆分。
- 可靠命令收据、容量窗口与待发命令槽在服务端与 SDK 间统一语义；Lucene 索引资源生命周期
  由两个搜索引擎共享，固定打开/回滚/关闭次序。
- 客户端本地缓存提供离线诊断与有界压实；移除过度设计的归档/隔离子系统，损坏缓存原位重建。
- 遥测补充媒体解码失败原因码；协议错误码与遥测准入策略下沉领域层。
- 无头客户端（tt-agent / CLI / MCP / ImBot 运行时）独立为 `client/headless` 模块，SDK 保持纯净。
- 发布通道标记（stable/preview/snapshot）贯穿 android.json 与客户端升级对话框；内测快照
  一律全量包，不产生增量链。

## 版本与升级

- 展示版本：`0.0.2`；构建计数：`2`；Android `versionCode` 与正式 Desktop revision：`3`。
- 协议：`0.2`，最低支持 `0.0`。本版冻结契约新增：`MENTION_SYNC`、`DOCUMENT_CHANGED`、
  `TASK_CHANGED/TASK_DUE`、`CHAT_DRAFT_CHANGED` 通知，`chatDraft`、`contentSearch`、
  `documentComment`、`task` 服务，`device/3` 多厂商推送注册与 `document/20` 单空间读取。
  `0.0.0`/`0.0.1` 的协议快照不可修改；v0.0.1 客户端可直接连接本版服务端（协商 minor 1）。
- 数据迁移：服务端新增一条迁移 `create_v0_0_2_tables`（建齐管理安全、评论、搜索、任务、草稿、
  推送注册与功能开关表并补 `conversations.mentioned` 列）；客户端 SQLDelight 以单步 schema 1→2
  迁移补齐 11 张新表。普通升级保留 PostgreSQL、RocksDB、文件、dataset、账号及本安装资料。
- im.virjar.com 开发环境本次清库重建（无真实用户）；曾安装 rev≤102 内测快照的设备需清理本地
  缓存后重新登录（触发的是拒绝降级保护，数据不被静默删除）。
- 构建、Server 与 Desktop 使用 JDK 21；Desktop 打包使用 JBR 21，Android 最低仍为 8.0，macOS 最低为 14.0。
- 公版下载入口为 [TeamTalk 站点](https://im.virjar.com)。私有版使用自己的下载站点和既有签名材料；
  部署与发行步骤见[发行手册](https://github.com/virjar/team-talk/blob/v0.0.2/doc/07-operations/releasing.md)。
  发行附件中的 Server ZIP 需要管理员单独部署。

## 已知限制

- 「@我」红点集合为进程内投影，客户端重启后随下一次置位/清除重建；纯文本 `@名字` 不构成
  协议级提及（只认结构化 mentions sidecar）。
- Android 后台推送依赖各厂商通道（小米/华为/荣耀/OPPO/vivo/魅族），私有部署需在部署 Profile
  配置相应厂商凭据；未配置的通道退化为进程存活通知。
- 文档按版本保存并检测冲突，尚无逐字符协同；远端文档和授权变化需要刷新。
- 日历、音视频通话和 iOS 客户端不在本版范围内。
- macOS 公证与 Windows 受信任签名尚未配置。跨平台构建不等于全部设备实机验收。
- 完整备份恢复演练与长期存储治理仍待完善，重要资料应保留原件。
