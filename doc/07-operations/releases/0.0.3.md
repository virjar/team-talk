# TeamTalk 0.0.3

> 发行准备稿。功能收口代码为 `18037c177f4b7c2a06a3912d6cdcb6502dcb5f71`；本文件不表示
> 已经发布。当前根配置仍为 `0.0.2 / build 2`，尚未创建 `0.0.3` 正式契约快照或 tag。

TeamTalk 0.0.3 将待办、文档与日常沟通连接起来，并统一桌面、Android 和无头客户端的构建与
下载入口。本版继续定位为开发者预览；建立版本 tag 和兼容基线不代表进入稳定产品阶段或完成签名、公证。
普通升级保留服务端数据与同一安装身份的客户端资料。

## 日常使用

- 待办任务：群聊上方展示共享待办卡片，为执行人显示未完成提醒横幅；支持 Markdown 描述、
  文档引用与附件。执行人延期时填写理由，系统保留原截止时间、延期次数和处理耗时。
- 日历式重复：支持每 N 周/月，涵盖每周、双周与每月；按首次日期与指定时区生成独立任务。
  当月没有 29、30 或 31 日时落到月末，下月恢复原日号。停用系列保留已经生成的任务。
- 文档工作区：改善文档树与正文恢复、跨空间多标签、评论和离线操作的衔接；并发编辑继续通过
  版本冲突处理，不承诺逐字符实时协同。
- 群邀请：分享可打开的邀请链接；在聊天中识别邀请 URL，并通过剪贴板线索进入预览与入群流程，
  常用会话与通讯录区域不再固定放置低频的“加入群”按钮。
- 桌面未读：修复切换群聊时沿用上一个会话消息序号导致误报已读的问题；旧的异常已读意图通过
  服务端当前会话历史核对后恢复，保留已经验证的真实阅读进度。
- 官网直接提供各平台的安装包、通道和版本记录，展示同号快照的源码身份；新增
  [TeamTalk QQ 交流群](https://qm.qq.com/q/cY2VP3O5OM)，群号 **964624703**，用于内测交流与问题反馈。

## 构建与可靠性

- 统一 Gradle 工具生成 macOS 双架构、Windows、Linux 桌面产物，以及 Android、Server 和 Headless 包。
  服务端发布注册中心管理制品、通道、停用与回滚；客户端不再依赖 Conveyor 生成新版本下载站点。
- 桌面壳与应用负载分离，支持应用内文件级更新；Windows 启动链正确保留中文路径与参数。
- 无头客户端提供 CLI、Agent 与 MCP，支持固定目录安装、身份明确的升级及有界授权。
- 修复会话关闭时后台索引工作仍访问已关闭缓存的问题；迁移和恢复保持可靠发件箱、草稿与命令身份。
- 首页产品介绍、下载与社区入口合并；本开发周期引入的独立 `/downloads` 页面已经删除。

## 从 v0.0.2 升级

- 计划发行配置：展示版本 `0.0.3`、根构建计数 `3`、Android `versionCode=4`、正式 Desktop revision `4`。
  正式准备时推进根配置、冻结协议快照并重新密封制品；不得把 `0.0.2` 开发快照改名为本版。
- 协议为 `0.3`，最低支持仍为 `0.0`。v0.0.2 冻结的 294 条 wire 记录保持原样，本周期新增
  29 条记录，首次出现版本均为 minor 3。旧客户端通过协商使用既有能力；新增能力需要新版客户端。
- PostgreSQL 在既有迁移 0–2 之后执行 3–7；客户端 SQLite 从 schema 2 升至 schema 5。
  保留 PostgreSQL、RocksDB、文件、epoch/dataset、账号以及本安装的草稿和可靠待发送操作。
  详细迁移定义见[持久化](../../06-server/persistence.md)。
- 先备份同一时间点的 PostgreSQL 与完整服务端 `data/`，再部署服务端，最后更新客户端。
  回退不能只替换旧 JAR：必须使用匹配的数据备份与部署流程，避免把新版数据交给旧代码处理。
- Android 沿用公版包名与签名，使用更高的 code 4 覆盖安装。私有发行必须使用各自既有身份与签名。
- 旧 Conveyor 桌面客户端需要一次手动下载安装新完整包；已有旧更新元数据保持只读可用，不能将
  “保留旧入口”理解为旧更新器能自动跨越构建工具迁移。更早 Windows MSIX 虚拟化资料目录的过渡
  仍需单独检查，未宣称自动迁移。新壳上线后使用其应用内更新流程。
- 私有内测节点由维护者单独确认升级与兼容过渡，不随公版网站部署自动更新。

## 验证范围与已知限制

- v0.0.2 冻结契约与当前协议基线、真实 PostgreSQL/SQLite 迁移、TCP 协商与事件版本投影均有
  回归入口。桌面群未读恢复、切换会话与窗口失焦收信已在公版真实客户端复验。
- Windows 原生 CI 验证实际启动器与随包 JVM 的中文参数，不能替代所有 Windows 版本的完整 GUI
  安装、升级与卸载矩阵。Linux 桌面完整 GUI 和 macOS 系统信任流程仍有验收范围限制。
- Android 8.0+ 为支持下限。API 35 的一套 16 KB 模拟器曾出现 ART 原生崩溃；当前版本的持续运行
  观察不能据此宣称该问题已经根治，也不能外推为物理设备验收。
- Android 后台提醒仍依赖电池策略及相应厂商推送配置。模拟器中仅应用处于 Unrestricted 策略的
  提醒闭环通过，默认优化策略与各厂商真机送达不在该结论内。
- 无头升级具备真实 HTTP 下载、摘要校验、错误回滚与进程互斥回归；最终公网通道到既有安装的
  整链升级验收需要在正式制品发布后补做。
- macOS 公证与 Windows 受信任签名尚未配置。iOS、音视频通话、通用会议日历不属于本版能力。
- 当前容量测试不是万级同时在线承诺；长期运行、完整备份恢复演练与更广设备矩阵仍需持续验证。

正式发布步骤与门禁见[统一发行流程](../releasing.md)；发行前按
[部署验收](../../09-testing/deployment-acceptance.md)核对实际制品和通道。
