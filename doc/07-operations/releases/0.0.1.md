# TeamTalk 0.0.1

TeamTalk 0.0.1 改善私有化部署、跨平台安装和日常聊天体验，完善异常恢复与运行状态检查。
本版继续作为开发者预览发布，普通升级保留已有服务端资料和客户端安装数据。

## 日常使用

- 图片、视频和文件消息可以保存到系统相册或本地文件系统；Android 按媒体类型处理权限和保存失败的清理。
- 用户资料展示所属组织与部门路径。群邀请通过搜索选择成员，并排除已在群内的用户。
- 群主转让后，群设置按当前成员角色展示操作；双端群设置支持完整滚动，窄屏附件面板和群文件按钮正常布局。
- 表情面板在输入区内展开，聊天头像可以打开用户详情；主导航和设置入口统一交互样式。
- macOS 关闭窗口后可从 Dock 重新唤回；Windows 改善安装后数据目录、托盘文本及跨平台原生依赖打包。

## 可靠性与运维

- 区分账号封禁与普通凭据失效。服务端提供权威封禁判定，客户端按账号清理失效资料，清理中断后可以继续恢复。
- 文档草稿的持久化与界面资源交接使用明确所有者，避免切换与关闭时丢失待处理状态。
- 修复客户端并发唤醒时旧状态覆盖新状态的问题，使草稿、已读状态和可靠业务命令恢复能读取最新的提交、认证和定时器状态。
- 服务端后台维护任务纳入健康检查；任务意外停止时 `/health` 返回不可用，避免遗漏消息投影恢复或清理任务故障。
- 大文件下载不会因入站空闲超时中断；Windows 安装站点支持 HEAD、Range 和安装文件所需 MIME 类型。
- 部署在停止旧服务前校验服务专用 Java 运行时；公版与私有构建可共用 Gradle daemon，SSH 加密实现保持隔离。
- 私有内测支持同展示版本的手动更新、独立安装身份与持续签名；Desktop 安装修订号由完整源码历史推导。

## 版本与升级

- 展示版本：`0.0.1`；构建计数：`1`；Android `versionCode` 与正式 Desktop revision：`2`。
- 协议：`0.1`，最低支持 `0.0`。组织资料 RPC 与账号封禁帧纳入本版冻结契约，保留 `0.0.0` 的协议快照。
- 从 `0.0.0` 或私有内测包升级，先部署服务端，再分发相同应用身份与签名的客户端。普通升级保留 PostgreSQL、RocksDB、文件、dataset、账号及本安装资料，无需清库或重新注册。
- 构建、Server 与 Desktop 使用 JDK 21；Desktop 打包使用 JBR 21，Android 最低仍为 8.0，macOS 最低为 14.0。
- 公版下载入口为 [TeamTalk 站点](https://im.virjar.com)。私有版使用自己的下载站点和既有签名材料；部署与发行步骤见
  [私有化部署指南](https://github.com/virjar/team-talk/blob/v0.0.1/doc/01-getting-started/private-deployment.md)及
  [发行手册](https://github.com/virjar/team-talk/blob/v0.0.1/doc/07-operations/releasing.md)。发行附件中的 Server ZIP 需要管理员单独部署。

## 已知限制

- Android 的后台通知依赖进程存活和系统联网许可，尚无进程被回收后的 Push 唤醒。
- 含内嵌图片或文件的未发送聊天草稿，以及未完成的资产上传，不支持跨进程完整恢复；请保留原文件。
- 文档按版本保存并检测冲突，尚无逐字符协同；远端文档和授权变化需要刷新。
- 文档与文件搜索、文档评论、任务、日历、音视频通话和 iOS 客户端不在本版范围内。
- macOS 公证与 Windows 受信任签名尚未配置。跨平台构建不等于全部设备实机验收，Apple Silicon 原生播放器等目标平台检查仍需补齐。
- 完整备份恢复演练与长期存储治理仍待完善，重要资料应保留原件。
