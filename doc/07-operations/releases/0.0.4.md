# TeamTalk 0.0.4

TeamTalk 0.0.4 是 0.0.3 的修正发行：0.0.3 的 macOS 包存在影响日常使用的严重缺陷，
本版更换桌面壳架构完成修复，同时包含无头客户端的一个数据一致性修复。开发者预览定位、
安装身份与兼容基线（协议 0.3）不变；服务端无需升级，普通升级保留服务端数据与客户端资料。

**0.0.3 的 macOS 桌面用户必须重新下载安装包**：缺陷位于安装包壳本身，应用内更新无法修复。

## 修复：macOS 桌面

0.0.3 的 macOS 包在 macOS 26 (Tahoe) 上存在三个平台级适配缺陷，本版将桌面壳更换为原生
JNI 启动器并整体修复：

- 顶部状态栏托盘图标不显示（系统要求托盘归属应用主进程，旧 shell 启动被静默拒绝）；
- 新消息通知无任何效果（系统移除了 Java 旧通知接口）；现以应用身份使用系统通知，
  首次使用请在系统授权提示中允许；
- Dock 图标显示为 Java 默认图标；下载错误架构的安装包双击无提示。现错架构包会弹出
  中文指引并跳转下载页，Apple 芯片与 Intel 双架构版本各自原生运行（不再依赖 Rosetta）；
- Dock 点击、通知点击恢复主窗口，关闭窗口隐藏到托盘等交互随之修复；
- 运行时由 JBR 切换为 Temurin JRE 21.0.12.1（前者托盘实现在新系统上失效），并新增
  跨平台 ad-hoc 代码签名以解锁系统通知授权。

已知限制：Apple Silicon (arm64) 包的实机验证尚未覆盖；系统通知被拒时回退的基础通知
不携带应用图标。

## 修复：无头客户端

- ImBot 拉取历史消息不再建立 UI 历史租约，改用独立只读查询；机器人会话不会影响
  用户客户端的阅读位置与已读状态。

## 升级与数据影响

- 桌面端：0.0.3 壳缺陷只能通过重新下载安装包修复；覆盖安装保留账号、会话与草稿。
  0.0.2 及更早版本仍可经应用内更新升级（负载层），但同样建议重新下载以获得新壳。
- Android：无功能变化，安装序号随本版递增，可直接覆盖安装。
- 服务端：协议 0.3 不变，无需升级；0.0.3 服务端可与本版客户端正常互通。
