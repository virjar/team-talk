# TeamTalk 0.0.7

发行日期：2026-10-10。本版把 MSG-01"消息轴心深化"批次（协议 minor 0.6）正式带给所有用户，
覆盖此前仅在内测快照通道验证的六项新能力。发行协议冻结为 **0.6**（最低支持 0.0），
旧客户端升级后即可见新能力；未升级的旧客户端收到的 0.6 新消息按既有占位规则降级显示。

## 用户可见变化

- **会话内线程**：消息可发起线程讨论，根消息下聚合"查看 N 条回复"入口，线程面板内
  集中查看与继续回复。线程归属由服务端按回复链推导，历史回复无需回填。
- **群公告**：群主/管理员在群设置维护公告，成员在聊天顶部看到公告条（点击看全文，
  可临时收起），公告变更实时同步。
- **定时发送**：输入框旁时钟入口，可指定未来时间由服务器投递（支持发起者离线）；
  待发列表可查看与取消，服务重启后仍按时投递。
- **消息稍后提醒**：消息菜单快捷设置提醒（1 小时后/明天 9:00），到点本机通知；
  提醒为本机事实，重启不丢失。
- **群已读列表**：消息发送者与群主/管理员可查看"已读情况"（阅读进度到该消息的成员）；
  普通成员不可见，避免社交压力。
- **长消息折叠阈值放宽**：正文超过 2,400 字符或 48 行才折叠（原 1,800/36），
  长内容更少被截断。
- **合并转发**：多选消息后一键合并转发到目标会话；接收者展开看到发送时冻结的快照，
  无需（也无需有权）读取原始会话。
- **1:1 通话日志**（0.0.6 快照期已上线，随本版正式化）。

## 升级与数据影响

- 普通升级保留全部资料（账号、消息、草稿、发件箱、群文件与文档）。
- 服务端 PostgreSQL 增加 `scheduled_messages` 与（更早的）`message_reminders` 相关结构；
  服务端必须升级到本版才能支持定时发送与线程查询，旧服务端配新客户端时这些功能
  明确报错降级，不影响其余能力。
- 客户端 SQLite 增量迁移（消息提醒表）；旧客户端收到 0.6 新消息类型时渲染
  "当前版本不支持此消息"占位，升级后自愈。

## 已知限制

- 线程不做全局未读聚合 inbox；稍后提醒为单机事实（多设备不同步）；合并转发
  展开为快照而非原消息定位；群已读默认仅发送者与群主/管理员可见。
- Android 厂商推送的六家真机验收、iOS 真机分发仍在推进中（与 0.0.6 一致）。
- 定时发送精度为分钟级（服务端 10 秒扫描周期）；循环定时与任务看板视图
  在后续批次评估。

## 内测背景

本版能力于 2026-10-09/10 在 snapshot 通道完成两轮验证（公网 + 私有节点，
Android code 7 / Desktop revision 356），期间发现并修复发布工具链快照重试缺陷、
线程查询页大小超契约、公告条入口命中区等缺陷。开发历史已按功能整理为 8 个提交。
