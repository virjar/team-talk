# AI 辅助部署（WorkBuddy / AI 助手引导）

目标读者：自己不写代码、但电脑上有 AI 助手（如 WorkBuddy）的用户。你可以把本章的提示词
整段复制给 AI 助手，由它在你的电脑上完成 TeamTalk 私有站点的全链路部署；你只需要准备资源、
回答 AI 的提问、在关键节点确认。

官方人工参考：[私有化部署](private-deployment.md)（AI 助手同样会阅读它）。从试用转向正式
运营时的加固（HTTPS 正式证书、签名、推送等）见[从试用到生产](trial-to-production.md)。

## 1. 你需要先准备什么

| 项目 | 要求 | 说明 |
|---|---|---|
| 一台 Linux 服务器 | 公网或内网可达，2 核 4G 起步，Linux x86_64/arm64 | 需要root SSH 权限；用户最终通过它的 IP 访问 |
| 一台你自己的电脑 | macOS / Windows / Linux，能装 JDK 21 | 构建与部署的发起端，AI 助手在这台机器上运行 |
| AI 助手的能力 | 能执行终端命令、能 SSH 到服务器 | WorkBuddy 等通用 Agent 均可；只会聊天不能执行的不行 |

不需要：域名（可先用 IP + 自签证书试用）、HTTPS 正式证书、数据库运维经验（PostgreSQL
由部署工具用 Docker Compose 自动拉起）。

## 2. 复制给 AI 助手的提示词

在使用前通读一遍并按需修改方括号内容；`git clone` 地址以官方仓库为准。

````text
请帮我部署一个 TeamTalk 私有化 IM 站点。你是执行者，我提供资源与决策。

## 资源
- 服务器：[服务器 IP]，SSH 端口 [22]，账号 [root]，我会配合完成登录
- 我的电脑：当前这台机器（你在这里执行构建与部署命令）
- 组织名称（客户端显示名，可后改）：[例如：某某公司内部通]

## 要求
1. 先阅读仓库内 doc/01-getting-started/private-deployment.md，严格按它执行，
   不要发明文档之外的步骤；遇到与文档冲突的做法，停下来向我说明。
2. 在我的电脑上：安装 JDK 21（如缺失）→ 克隆仓库 → 生成 TCP 自签证书 →
   编写 buildSrc/deployment-local/Deployment.kt（服务器 IP、组织名称、
   应用身份按文档 §2；身份一旦确定不要再改）。
3. 首次部署：运行文档 §4 的 deployServer 命令。首次部署会在本地生成
   deployment.secrets（数据库与管理员随机密码），绝对不要把它提交到 Git 或发给我以外的任何人。
4. 部署完成后执行文档 §7 的健康验收（curl /health 应返回 UP）。
5. 引导我完成管理后台初始化：告诉我 deployment.secrets 里的 ADMIN_USER/ADMIN_PASSWORD，
   打开 http://[服务器IP]/admin 登录，并督促我在「管理安全」页修改管理员密码。
6. 发布客户端安装包：按文档 §8，先 private-first 模式发布一次预览包，
   让我能在 http://[服务器IP]/ 下载到 macOS/Windows/Android 客户端。
7. 每完成一步，用一句话向我汇报进度与下一步；需要我做决策时给出选项而不是开放式提问。

## 边界
- 只操作我的电脑与我的服务器；不把任何凭据写入代码仓库或发给外部服务。
- 服务器上如果已有同名部署或数据，先停下来问我，不得覆盖。
- 全程不修改业务源码；部署配置只放在 buildSrc/deployment-local/（被 Git 忽略）。
````

## 3. 你需要在过程中配合的事

1. **SSH 登录**：把服务器密码给 AI 助手执行，或按它的指引配置密钥（推荐密钥）。
2. **确认应用身份**：AI 会问应用名/包名——这是客户端的安装身份，**发布给用户后不能再改**，
   想清楚再答（详见[客户端发行身份](../07-operations/configuration.md#客户端发行身份)）。
3. **保管两个东西**：
   - `buildSrc/deployment-local/` 整个目录（部署配置 + 凭据 + 证书），交接、备份、换电脑都靠它；
   - 管理后台新密码。
4. **验收**：手机装 Android 包或电脑装桌面端，注册一个账号，发条消息、传个文件。

## 4. 常见卡点（AI 助手处理不了时）

| 现象 | 处理 |
|---|---|
| 构建机首次构建下载依赖很慢 | 正常，Gradle 需要拉取 Node.js 与 npm 依赖；网络受限时配置镜像后重试 |
| 服务器 5100/80 端口被占用 | 让 AI 改用其他端口（配置里 tcp.port 与 http url 端口一致） |
| deployServer 中途失败 | 重跑同一命令即可；工具是幂等的，不会留下半安装状态 |
| 忘记管理员密码 | 在服务器上以环境变量方式重置，见[管理员凭据与恢复](../07-operations/configuration.md#管理员凭据与恢复) |

## 5. 之后

- 日常升级：让 AI 助手阅读[部署与升级](../07-operations/deployment.md)后执行 upgrade 流程；
- 转正式运营：按[从试用到生产](trial-to-production.md)逐项加固；
- 反馈问题：把服务端日志（管理台「日志」页）与操作时间点记录下来。
