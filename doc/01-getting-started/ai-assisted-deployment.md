# AI 辅助部署（WorkBuddy / AI 助手引导）

目标读者：不懂 git、不懂服务器的普通人，但电脑上装了能执行命令的 AI 助手（如 WorkBuddy）。
你不需要看懂任何命令——AI 负责全部技术操作；你只负责四件事：

1. 注册云账号并付款（买一台服务器）；
2. 在几个节点做决定（起什么名字、用什么密码）；
3. 配合输入密码 / 验证码；
4. 最后用自己的手机验收。

整个流程的概念图（不需要理解术语）：

```text
AI 从 GitHub 把源代码下载到你的电脑（代码是开源公开的）
   → AI 在你电脑上打包成服务端程序
   → AI 通过网络把它装到你买的服务器上
   → 你和朋友用手机/电脑下载客户端，注册就能聊天
```

**代码下载成功后，你就已经成功了一大半**——之后的所有命令都由 AI 执行。

源代码地址（GitHub 开源仓库，AI 助手直接使用，不需要你注册 GitHub 账号）：

```text
https://github.com/virjar/team-talk
```

人工参考文档（AI 助手会阅读，你不需要读）：[私有化部署](private-deployment.md)。
转正式运营的加固见[从试用到生产](trial-to-production.md)。

## 1. 买服务器：两种模式

### 模式 A：AI 分阶段指引，你操作云控制台（推荐默认）

账号、付款、实名认证涉及你的身份与财产，**始终由你本人操作**；AI 负责在每一步告诉你
点哪里、选什么。以阿里云为例（腾讯云路径类似，AI 助手按你选的厂商引导）：

| 阶段 | 谁做 | 要点 |
|---|---|---|
| ① 注册与实名 | 你 | 打开 aliyun.com（腾讯云为 cloud.tencent.com）注册账号并完成实名认证；需要手机号与支付宝/银行卡 |
| ② 购买实例 | 你点，AI 指路 | 控制台搜「云服务器 ECS」（腾讯云为「CVM」）→ 创建实例。规格选 **2核4G**（个人/小团队够用，每月几十元量级；新用户常有机会拿到低价试用，可让 AI 帮你找试用入口）；系统镜像选 **Ubuntu 24.04**；系统盘 40G 起 |
| ③ 安全组 | 你点，AI 指路 | 试用只需要放行 **80**（网页与客户端下载）和 **5100**（消息通道）两个端口；22（SSH）通常默认开放，AI 拿到 IP 后会自动探测，不通再补；**443 不用开**——它属于正式运营阶段的 HTTPS（见[从试用到生产](trial-to-production.md)），试用期不需要 |
| ④ 设置登录方式 | 你 | 给实例设置 root 密码（自己想一个并记住）；更推荐密钥对——如果你不会，让 AI 在你电脑上生成后帮你在控制台导入 |
| ⑤ 拿到公网 IP | AI 核对 | 实例列表里的「公网 IP」，告诉 AI 或让 AI 帮你从页面读出来 |

### 模式 B：AI 直接操作你的浏览器

如果你的 AI 助手支持浏览器操作：你完成账号登录后，可以让它代你在控制台点选配置、核对
安全组、读取公网 IP。**三条红线**：支付确认、密码/验证码输入、实名认证，永远你本人操作，
AI 不得代输也不得记录你的云账号密码。云厂商控制台界面会更新，页面与 AI 所述不一致时，
以实际界面为准并让 AI 按当前页面重新引导。

已有服务器（公司给的、以前买的）？直接跳到第 2 步。

## 2. 复制给 AI 助手的提示词

按方括号提示修改后整段复制。

````text
请帮我从零部署一个 TeamTalk 私有聊天站点，给我的团队/朋友使用。你是执行者，
我不懂技术，所有命令由你执行；涉及付款、密码、验证码的环节引导我本人操作。

## 我的情况
- 云厂商与账号：[阿里云 / 腾讯云 / 已有服务器（直接给 IP）]
- 服务器：[还没有，请你带我买 / 已有，IP 是 ____，root 密码我会配合输入]
- 组织名称（聊天软件显示的名字，之后可以改显示但不建议改）：[例如：星辰科技内部通]

## 部署要求
1. 服务器准备（若尚未购买）：分阶段带我操作云控制台——我负责注册、实名、付款和
   设置密码，你负责告诉我每一步点哪里、选什么。规格 2核4G、镜像 Ubuntu 24.04、
   安全组试用只需放行 80 与 5100（443 属正式 HTTPS 阶段，现在不开；SSH 的 22
   通常默认开放）。若你具备浏览器操作能力且我已登录控制台，可代我点选配置与读取
   公网 IP，但支付、密码、验证码、实名认证永远由我本人操作。
1.5 拿到服务器 IP 后先自动探测：验证 SSH（22）可达、80/5100 端口从我的电脑
   可连通；不通就把缺少的安全组规则一条条指给我补，补完自动复测，不要让我猜。
2. 在我的电脑上：安装 JDK 21（如缺失）→ 从 https://github.com/virjar/team-talk
   克隆源代码到我的用户目录 → 生成证书 → 编写部署配置（服务器 IP、组织名称按
   文档 §2；应用身份确定后不要再改）。
3. 首次部署：运行仓库文档 doc/01-getting-started/private-deployment.md §4 的
   deployServer 命令。部署会在本地生成 deployment.secrets（数据库与管理员随机密码），
   不要提交到任何代码仓库，也不要发给任何人。
4. 部署完成后按文档 §7 验收（curl /health 返回 UP）。
5. 管理后台初始化：告诉我 deployment.secrets 里的 ADMIN_USER/ADMIN_PASSWORD，
   引导我打开 http://[服务器IP]/admin 登录，并督促我在「管理安全」页修改管理员密码。
6. 发布客户端：按文档 §8 以 private-first 模式发布预览包，让我在
   http://[服务器IP]/ 下载到 macOS/Windows/Android 客户端。
7. 每完成一步用一句话汇报进度与下一步；需要我决策时给选项，不问开放式问题；
   卡住超过两轮就把完整错误信息给我看并解释人话版本的原因。

## 边界
- 只操作我的电脑与我的服务器；绝不处理我的支付、云账号密码、验证码。
- 服务器上已有同名部署或数据时先停下问我，不得覆盖。
- 不修改业务源码；部署配置只放 buildSrc/deployment-local/（该目录不进版本库）。
````

## 3. 过程中你要配合的事

1. **SSH 首次登录**：AI 连服务器时需要输 root 密码——你输入即可；AI 可随后配置免密登录
   （推荐），之后不再需要输。
2. **两个决定想好再答**：组织名称、应用包名（客户端安装身份，**发给用户后不能改**，
   详见[客户端发行身份](../07-operations/configuration.md#客户端发行身份)）。
3. **保管两样东西**：电脑上的 `buildSrc/deployment-local/` 整个目录（配置+凭据+证书，
   换电脑/交接全靠复制它）；管理后台新密码。
4. **验收**：手机装 Android 包，注册一个账号，发条消息、传个文件、给同事也装一个互发。

## 4. 常见卡点（让 AI 按此处理）

| 现象 | 处理 |
|---|---|
| 云控制台页面和描述不一致 | 控制台会改版；让 AI 按当前页面文字重新引导 |
| 安全组漏了 80 或 5100 | AI 拿到 IP 后会自动探测端口，发现不通会指明要补的规则；典型症状是“网页打得开但收不到消息”（缺 5100） |
| 首次构建下载依赖很慢 | 正常现象（要拉取构建工具链）；网络受限时让 AI 配置镜像源重试 |
| deployServer 中途失败 | 直接重跑同一命令；工具是幂等的，不会留下半安装状态 |
| 忘记管理员密码 | 服务器上以环境变量方式重置，见[管理员凭据与恢复](../07-operations/configuration.md#管理员凭据与恢复) |
| 服务器重启后服务没起来 | 部署已注册系统自启，一般会自动拉起；没起来就让 AI 查 `systemctl status teamtalk` |

## 5. 之后

- 日常升级：让 AI 阅读仓库内[部署与升级](../07-operations/deployment.md)后执行；
- 交给真实用户前：按[从试用到生产](trial-to-production.md)逐项加固（AI 可以代为核查）；
- 遇到产品问题：从管理台「日志」页取服务端日志，连同操作时间点反馈给开发者。
