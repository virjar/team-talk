# 开发者预览版与小范围内测

开发者预览版的目标是让少量使用者完成真实沟通和轻量办公协作，收集现有功能的断点。
它不以补齐日历、通话或新的应用平台为前提，也不代表稳定版承诺。已发行的能力和
安装边界见 [0.0.3 发布说明](../07-operations/releases/0.0.3.md)；当前协议为 0.3，最低支持 0.0。
体验时使用配套的服务端与客户端构建，不能由相同展示版本推断开发快照的协议能力。

## 体验范围

| 可以体验 | 使用方式与边界 |
|---|---|
| 注册、登录、资料与好友 | 自行注册，按用户名搜索另一名体验者并添加好友；普通私聊和建群不依赖管理员先配置组织 |
| 私聊、群聊、搜索与收藏 | 文字、回复、编辑、撤回、表情回应、已读、静音和保存的消息使用现有入口 |
| 文件、图片、语音和视频 | 上传完成后发送；媒体完整下载到本地后播放，已缓存内容可离线读取 |
| 群共享文件 | 从群设置进入；支持目录、上传、版本、重命名和删除；聊天附件不会自动成为群文件 |
| 企业文档 | 创建空间并授权，按版本保存；冲突时保留草稿。Protocol 0.2 支持变更提示与文档级评论，评论不改变正文修订 |
| 任务协作 | 基础读写、状态与审计自 protocol 0.2 可用；protocol 0.3 支持群卡片、Markdown、材料、延期与每 N 周/月重复，见[待办任务](../02-product/tasks.md) |
| 受控通知机器人 | 从群设置创建，供 CI、监控等系统向指定群发送通知；接入见[机器人说明](../05-clients/notification-bots.md) |
| 开发者 SDK / CLI | 下载无头分发包，提供 Agent、CLI、MCP 和固定目录安装与升级；权限与平台边界见[无头客户端](../05-clients/headless.md) |

建议以 **Desktop 为主要使用端，Android 为配套体验端**。这是一项范围建议，不能将尚未验证的
操作系统列为支持平台；交叉打包能生成对应文件，不代表该安装包已经能在目标机器顺畅使用。
实际开放的系统与架构以对应发行包的安装验证范围为准。

iOS 已接入同一 SDK 与共享界面，并完成 Apple Silicon 模拟器全链路验收（登录认证、事件同步、
心跳保活），列为开发者预览受支持平台；但真机签名与 APNs 验收未完成，且 iOS 没有下载即装的
制品形态——在组织取得 Apple 签名与 TestFlight 分发材料前，iOS 不进入内测分发清单，
渠道评估见 [iOS 分发与安装渠道](../05-clients/ios.md#分发与安装渠道)。

## 开始使用前需要知道

- Android 已接进程存活通知及国内厂商官方推送，实际厂商送达仍须按安装包配置与真机验收；Android 13
  及以上需要允许通知权限，拒绝不影响聊天。未配置或未经验证的厂商通道不能保证进程回收后的及时通知；
  具体边界见[Android 后台通知](../10-reference/roadmap.md#client-07--android-后台唤醒与系统通知)。
- 普通与含图片/文件的聊天草稿、上传意图、已进入发送队列的消息均可持久恢复；READY 富草稿可通过
  protocol 0.2 在同账号设备间同步。未上传源文件仍只属于本安装，不能由另一台设备代为恢复。
- 文档采用共享版本与冲突检测，不提供逐字符协同。Protocol 0.2 的变更事件自动刷新有界驻留内容；
  远端新修订仍保留本机未保存正文，不能直接覆盖草稿。评论提交后持久排队；尚未提交的输入只在当前
  工作台会话保留，具体边界见[企业文档](../02-product/documents.md#文档评论)。
- 缓存过的文档正文可以离线续写并保留本机草稿，联网后保存；从未缓存的正文不能离线打开。
- 全局搜索提供消息、用户、文档标题/正文、群文件名与聊天附件文件名查询；内容结果打开时重新校验当前权限。任务通过独立栏目访问，不进入全局搜索；日历尚未实现。
- 兼容评审以正式 tag 为基线，同号开发快照不承诺彼此兼容；普通升级保留数据。未来破坏性变更须明确迁移与影响，完整备份恢复演练仍需完成。
  只放可重新取得的试用资料；如果需要把它作为日常主力工具，先完成
  [REL-01 数据基线与恢复](../10-reference/roadmap.md#rel-01--数据发布基线备份与恢复)。

## 组织一次内测

```mermaid
flowchart LR
    Scope["确定测试实例与目标平台"] --> Build["同一提交构建候选包"]
    Build --> Server["部署匹配服务端"]
    Server --> Smoke["轻量业务冒烟"]
    Smoke --> Install["目标机器安装与关键操作"]
    Install --> Share["记录版本和限制后定向分发"]
    Share --> Feedback["按复现步骤修复现有断点"]
```

1. **确认数据用途。** 默认 `im.virjar.com` 是需要保留资料的开发/内测实例。
   普通部署保留数据，破坏性重建必须另行明确范围与影响。正式发行点位之间需要兼容评审；
   试用者应保留重要资料的原件，内部开发按[版本与兼容机制](../04-protocol/versioning.md)推进迁移。
2. **固定构建来源。** 使用一个已提交、工作区干净的 commit 构建服务端和客户端，记录版本、完整 commit、
   服务端 `/health` 的 `buildIdentity` 和候选文件 SHA-256。私有实例的客户端默认连接配置在构建时写入，
   参见[私有化部署](private-deployment.md)与[Desktop 制品构建](../07-operations/desktop-cross-build.md)。
3. **先部署再验证。** HTTP(S) 与 TCP TLS 按选中的部署配置连接，支持 HTTP + 自签 TLS/TCP；`/health`
   为 UP 后在独立测试实例执行业务冒烟。真人使用的实例先进行健康与下载检查，再复验约定的用户流程，
   不自动创建测试账号。健康检查不能替代登录和文件访问。
4. **安装真正要分发的包。** 至少在每个承诺支持的平台实际安装、打开，并用两个账号完成下表；保留安装包
   的原文件，验证后直接分发该文件，不重新构建一个未经核对的替代包。
5. **记录已知限制再邀请。** 预览包可使用开发签名，但不得称为正式签名、公证版本。安装渠道与升级方法
   随包写清；切换 Android 签名不能靠要求用户清除数据来掩盖不兼容。

### 轻量业务验收

```bash
./gradlew :server:server:previewSmokeTest
```

仅在独立测试实例执行；真人使用实例的数据规则见[测试数据归属](../09-testing/deployment-acceptance.md#测试数据归属与真人内测实例)。
该任务连接当前选中部署配置函数的目标，复用 `RemoteAcceptanceTest` 中带 `preview-smoke` 标签的
九个业务场景：注册后登录、群聊广播、普通附件、富文本附件、文档冲突与撤权、群文件版本与下载、
双设备重连收敛、表情回应、保存的消息与搜索。通过真实 SDK、TCP 和 HTTP 操作已部署服务，
不启动另一个模拟服务。测试会创建 `e2e-` 前缀的体验账号和相应业务数据。

它不重启或强杀服务器，不执行容量测试，不依赖组织管理凭据，也不改变宿主机网络。
报告在 `server/server/build/reports/tests/previewSmokeTest/index.html`；每次实际执行，不复用旧的成功报告。
完整发布验收仍使用 `:server:server:acceptanceTest`，不要把冒烟通过写成完整发布门禁通过。

### 候选安装包最小人工检查

| 过程 | 通过条件 |
|---|---|
| 安装 → 注册 → 退出 → 登录 | 表单失败可原地修正，提交有等待反馈，登录后进入会话列表 |
| 两个账号互加好友 → 私聊/建群 | 对端收到文字；搜索能回到对应消息；重开应用能看到历史 |
| 发一张图片和一个普通文件 | 对端能下载打开；下载失败可重试；返回聊天仍可继续输入 |
| 创建文档 → 授权 → 双方修改 | 另一人刷新可见；保存冲突保留草稿，能选版本后继续保存 |
| 群文件上传 → 改名 → 追加版本 | 另一成员刷新或收到变更后能看到最新条目，旧版本能读取 |
| Android 按 Home → 对端发消息 → 点击通知 | 授权后后台出现提醒并回到对应会话；前台、静音会话不打扰；拒绝通知权限仍能聊天 |
| 关闭再打开应用 | 已登录账号能恢复；未确认的发送状态与历史不冒充成功 |

这是一轮短路径检查，不扩展成完整 UI 自动化。布局、系统权限和安装行为只能由实际客户端确认，
不能用 SDK 冒烟代替。失败时先修复或缩小该平台的预览范围，再分发。

## 反馈如何形成可执行任务

体验者只需给出：**安装包版本或文件名、操作系统、发生时间、操作步骤、预期结果和实际结果**。
可附截图，但不要贴密码、token 或完整私密聊天。维护者结合对应构建和现有日志定位；
新问题优先按“已有功能正常流程受阻 → 已有功能恢复不清楚 → 新功能建议”处理。

当前能力事实见[功能状态](../10-reference/feature-status.md)，仍需开发的项目见[路线图](../10-reference/roadmap.md)。
