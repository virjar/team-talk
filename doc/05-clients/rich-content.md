# 富文本与媒体

## 1. 单一文本模型

所有文字消息使用 `RICH_TEXT`。Markdown 是持久化和传输的权威源，WYSIWYG 编辑器只是它的
交互表示；`plainText` 与 mentions 每次由 Markdown 重建。
发送、编辑、搜索、通知预览和 SDK 共用这一条文字路径。

## 2. 编辑器

仓库内 `richeditor/` 是 compose-rich-editor 的受控 fork，治理说明见 `richeditor/FORK.md`。聊天输入和
企业文档共用一套命令层与 `BasicRichTextEditor`，但按使用频率展示不同工具：

- 宽屏聊天常驻粗体、斜体、删除线、行内代码、链接、项目符号和编号列表；窄屏只常驻
  表情、语音、附件与发送，把低频格式收进可展开的“更多格式”，避免工具栏挤压正文输入。
- 聊天输入提供“可视 / Markdown 源码 / 预览”三种模式。源码是权威草稿，可直接
  编写或粘贴 AI 产生的标题、递归引用、代码围栏、任务列表和 GFM 表格。
- 只有可视编辑器能无损往返的 Markdown 才能切回可视模式；高级结构不做有损转换。
  未修改的可视内容仍保留用户原始 Markdown 写法，不因打开或切换模式被规范化改写。
- 预览与最终消息气泡使用同一渲染器，不允许“预览可见、发送后消失”。
- 文档额外提供撤销/重做、正文与 H1-H6、列表升降级；保存、预览、历史属于文档动作，
  不混入格式命令。
- `toMarkdown()` 生成消息源；不含上下文资产的聊天草稿使用 Markdown 双向恢复。带内部资产 URI 的
  聊天草稿还不具备可跨进程/跨设备的 sidecar 持久化，具体边界见下文。
- 链接对话框只接受 `http`、`https`、`mailto` 或可补全为 HTTPS 的域名，选择文字后可直接加链。
- Desktop Enter 换行，Cmd/Ctrl+Enter 发送。
- 窄屏聊天把行内代码、删除线和列表收进“更多格式”，常用入口不会被横向裁掉。
- 表情插入当前光标并恢复焦点。
- 编辑已有文字消息时重新载入 Markdown，高级内容自动进入源码模式；编辑会话与
  普通草稿互斥，取消或服务端确认保存后恢复原草稿。
- 已发消息的乐观编辑只存在于当前有租约的内存窗口，不把未确认正文写入 SQLite；同消息全局排他，
  失败只在没有更新通知、撤回或历史投影胜出时精确恢复。服务端同值回显也按来源胜出，不能被迟到的
  网络失败回调覆盖。

工具栏只暴露能够稳定写回 Markdown 的语义。字体族、任意字号、颜色、背景色和对齐目前不进入权威
Markdown，因此不能为了“按钮多”伪造会在保存后消失的格式。

企业文档在 Markdown 之上建立无损块级投影：普通正文继续使用富文本编辑器，引用、代码围栏和 GFM
表格使用各自的可视编辑块。未编辑块保留自己的原始源码切片，保存时逐字写回；只重新编码用户明确
修改的块。TeamTalk 上下文图片与文件是独立的无损资产块；任务清单、原始 HTML、引用式链接等
尚未产品化的扩展只退化为所在块的源码卡片，
不能把整篇文档切成纯文本。整篇 Markdown 源码仍作为用户主动选择的高级入口，而不是自动降级路径。
预览和历史版本使用同一文档块模型，不能静默省略代码、引用、表格或未知块。

富文本状态只能在 UI 线程读取，但正文上限允许达到 100 万字符，因此按键事件不直接串行化整个块或
整篇文档。块级 Markdown 投影以第一次变更打开固定短窗口，窗口内后续输入只替换待发布状态而不重启
计时，并在窗口末读取和发布最新内容；文档级编码只随已发布的块快照失效。切换模式、关闭标签和应用
退到后台时则绕过合并窗口，同步抓取编辑器最后一拍，再交给有界草稿持久化队列。

fork 的 TeamTalk 修改必须以 `[TT]` 注释和登记表维护，方便以后与上游比较。

## 3. Markdown 渲染

渲染层使用 JetBrains Markdown parser，转换为内部块和行内模型，再映射 Compose：

- 段落、标题、列表、任务列表、递归引用、代码块、分隔线和 GFM 表格；有序/无序列表、
  原始序号、嵌套层级、代码语言与
  表格对齐不能在投影时丢失。
- 粗体、斜体、删除线、行内代码与链接。
- 编辑器生成的 CommonMark 标点转义必须在气泡、链接点击、mention 派生字段和搜索纯文本中一致解码。
- `mention://uid` 链接渲染为可点击提及。
- 未闭合或未知语法保留可复制的等宽源码，不丢字。
- 不执行原始 HTML，Markdown 图片不加载第三方 URL；只有当前消息/文档 sidecar 授权的
  `teamtalk-asset://asset/<uuid>` 才可交给认证媒体管线。畸形、缺失或跨上下文引用显示可读源码，
  不解析全局 ID，也不进入普通 URL 点击回调。

渲染结果按 content 缓存，不能在每次 Compose 重组中重复解析。颜色来自当前气泡 contentColor，
确保进入浅蓝/灰色气泡时仍有正确对比。

### 上下文内嵌资产

Markdown 是位置权威，`EmbeddedAsset` 清单是资源元数据权威。图片和文件分别使用标准
`![alt](teamtalk-asset://asset/<uuid>)` 与 `[label](teamtalk-asset://asset/<uuid>)`，不把本地路径、
HTTP 下载地址或 FileStore path 写进正文。每次渲染只建立当前内容清单的局部 resolver，
不提供跨消息/跨文档的全局回退。

阶段一已接通的平台入口为：

- 聊天 Desktop：系统图片/文件选择器、文件拖放、二进制剪贴板粘贴。
- 聊天 Android：系统图片/文件选择器、二进制剪贴板粘贴。
- 文档 Desktop：主窗口与独立文档窗口都支持系统图片/文件选择器、文件拖放、二进制剪贴板粘贴；普通文本粘贴仍交由编辑器。
- 文档 Android：提供系统图片/文件选择器，以及编辑状态下的显式“粘贴”入口和
  物理键盘 `Ctrl/Meta+V` 二进制剪贴板导入；普通文本粘贴仍交由当前聚焦的编辑器。
  当前不提供 Android 文档拖放。

入口选中本地资源后，编辑器先分配 scope-local UUID 并插入稳定 Markdown 节点，
并行执行预处理与认证 HTTP 上传。上传结果只替换该 UUID 对应的 descriptor，不改写正文位置。
由于可视编辑器尚无无损的源码光标映射，从可视模式导入时会在正文末尾插入资产节点并切换到
Markdown 源码模式；当前不承诺 WYSIWYG 光标位置插入。

提交屏障必须同时证明：所有被正文引用的活跃 job 已 READY、Markdown 内部引用与清单精确闭包、
没有孤儿/重复 job。失败、取消或还在上传的资源都不得随消息或文档提交；用户在上传期间删除的
Markdown 引用不会因 READY 回调被重新插入。页面切换时的 job 事件以聊天/文档 owner key 隔离并在原 owner
返回时重放，不得把 A 的资产发布到 B。

Chat 与 Document 共用固定最大高度、可滚动的待处理资产列表，慢上传或多项失败不能把正文编辑区挤出
屏幕。准备/上传中的项目显示“取消上传”，失败项目同时显示“重试”和“移除”。取消与移除都先从 Markdown
删除该 UUID 的全部语义引用，并把删除后的聊天会话草稿或文档草稿发布/持久化到当前 owner；随后才
best-effort 取消平台上传任务。重试不改写 Markdown 位置或 sidecar，而是在当前进程内复用原 `jobId`、
`assetId` 和 `AttachmentUploadIdentity`；FAILED 到 PREPARING 只有一个并发调用能够胜出，旧 attempt 的迟到
状态不能覆盖新 attempt。列表始终按当前 Markdown 的语义引用过滤，所以取消返回失败或上传结果迟到为
`READY` 都不会让用户已经移除的资产节点重新出现。

同进程重试只保留完成这次导入所需的平台源。Android 首次准备后把 content URI 冻结为不可变
`PreparedMedia`，后续 attempt 复用同一快照；Desktop 不复制 picker/drop 原文件，只管理自己创建的剪贴板
临时文件。失败会保留这些源，READY、取消/移除或会话关闭才释放；Desktop 永不删除用户原文件。owner
离开后返回时只重放 PREPARING、UPLOADING 或 FAILED 状态，不重复插入 Markdown 节点。

已发布的 `RICH_TEXT`、`REPLY` 消息和文档快照都同时持久化 Markdown + canonical sidecar。接收端只按该上下文
sidecar 解析内部 URI，并使用当前会话的 Bearer 凭证经过实时消息/文档 ACL 渲染图片或下载文件；历史修订
保留各自的 sidecar，不用当前清单反推。聊天中的内嵌图片可点击进入当前会话的统一媒体画廊，画廊
身份由 `clientMsgId + assetId` 确定，不能用可能重复的存储 path 猜测初始页。

当前明确的阶段边界：

- 聊天的完整富资产编辑上下文只保留在已认证会话内存中。现有会话草稿后端只能原子保存一个 Markdown
  字符串，因此含内部 URI 的草稿不会被裸写入 SQLite 或跨设备草稿流；进程重启、退出账号或换设备后
  不保证恢复这类未发送内容。
- 没有将本地选择 token/源文件持久化为可跨进程恢复的上传命令，因此不支持断网选附件后自动续传的真正
  离线附件 outbox。
- 上传失败项支持当前进程内就地重试或移除，但重试状态、本地源和上传命令都不跨进程持久化；上传取消
  同样只作用于当前进程任务，二者都不能替代有界 spool/outbox。

回复消息的被引用摘要仍由服务端按目标消息重建；用户本次输入的作者正文则与普通 `RICH_TEXT` 共用
Markdown + sidecar 构建、上传屏障、接收端渲染和画廊聚合，不能用客户端提交的 quote 字段伪造目标摘要。

上述取消/移除交互已通过 Desktop 与小米 Android 真机的聊天、文档真实 picker 大文件导入、当前进程
取消、离开及重开验收，重开后正文不含被移除资产 URI。Android 截图同时确认了待处理卡片、
“取消上传”入口和取消后的可编辑正文状态。

Desktop 与小米 Android 就地重试都已真实覆盖聊天和文档：只停止部署配置指向的 TeamTalk 服务触发
FAILED，快速双击“重试”只启动一次；恢复服务后原节点上传成功，消息可发送、文档可保存，离开并重新
进入后内容仍可见。验收全程保持宿主机和手机网络连接。Android 还用 64 MiB 文件复现了上传过程中同一
账号 access token 轮换：服务端成功回执不再被误判为失败，若传输本身撞上旧凭据则只用同一 source、plan
和上传 identity 自动精确重放一次，进度不倒退，第二次失败仍交回上述人工重试入口。
本轮 Desktop/Android 语义树、截图与服务恢复记录保存在
`build/acceptance/client04-rich-asset-retry/`。

本地选择 token 只存在于页面临时 job，不进入 Markdown、持久草稿、协议或遥测。

## 4. 提及

用户选择候选后写入：

```markdown
@[显示名](mention://uid)
```

编辑器显示为 `@显示名`，但导出仍是上述 Markdown。服务端会从 Markdown 重新构建 mentions，
不信任调用方提供的侧信道列表，并在成功回执前确认每个 mention uid 都是当前会话成员；非法
mention 直接拒绝，不能触发通知语义。

群聊候选来自群成员；私聊候选来自对方/联系人。`@` 前缀需要行首或空白边界，避免邮箱误触。

## 5. 斜杠指令

行首 `/` 触发本地命令补全。`/shrug`、`/todo`、`/code` 等本地命令仅在新消息的可视模式发送前
展开；Markdown 源码和编辑已发消息均原样透传。服务端或 bot 指令需要独立权限、路由和结果模型。

## 6. 交互卡片

Markdown 源码用于“静态且安全的富表现”：标题、引用、代码、表格、任务状态和链接。
`INTERACTIVE_CARD` 是独立消息类型，用于按钮、表单、回调和可变业务状态。卡片使用结构化 schema
表达标题、区块和 action，不允许通过 HTML/JavaScript 或自定义 URL scheme 伪装交互。action 只提交
稳定 action id，服务端重新读取原消息并校验消息、用户和动作权限。

## 7. 媒体处理

### 上传

图片与视频先通过 HTTP 上传。服务端在存储源文件前生成缩略图和媒体元数据：图片使用 Java2D，
视频使用内嵌 FFmpeg/JavaCV；两者都运行在有并发上限和硬超时的可终止 helper JVM 中，失败时原文件
仍可无缩略图成功。响应提供 path、缩略图 path、尺寸和时长。

Desktop、Android 与 ImBot 共用 SDK 的流式上传契约：本地文件每次重试重新打开，以 64 KiB 级分块
写入固定长度 multipart，不把大附件整体读入堆。文件名和 Content-Type 在进入 multipart header 前
清洗，认证请求不跟随重定向，响应按上限读取。Repository 属于认证会话；同 uid 的 access 轮换在
下一请求生效，uid 变化或会话关闭立即拒绝后续传输。

### 气泡

- 图片/贴纸：媒体贴边并在 `240×320dp` 上限内单比例完整适配，只裁圆角边界，不裁正文内容。
- 视频：有元数据时按原比例完整适配；无元数据时使用 16:9 占位，并显示播放按钮和时长角标。
- 语音：播放/暂停、确定性波形和当前/总时长。
- 文件：使用独立卡片表面，包含扩展名色块、最多两行名称、大小、下载进度和重试；富文本中的
  图片与多个文件之间必须有稳定留白，不能视觉粘连成一个不可辨识的大块。
- 聊天中的 UTF-8 TXT 与 Markdown 文件默认在应用内预览：Android 进入独立页面，Desktop
  打开 700×520 小弹窗；Markdown 复用消息安全渲染器，TXT 保留可选择、可滚动的纯文本。
  单次内存预览上限为 512 KiB，超限或不支持的字符集可改用系统应用打开，其他文件类型仍沿用
  平台默认应用。
- 回复：引用竖线、发送者和截断内容，再显示正文；发送者快照由服务端根据同一会话内的目标消息
  重建，客户端只在旧快照为 UID 或为空时按 `replyToSenderUid` 安全补全。

### 缓存

Desktop 使用数据根拥有的统一媒体缓存。身份目录为
`<data>/media_e2/<sha256(deployment-fingerprint + datasetId + uid)>`；其中 deployment fingerprint 同时绑定
canonical TCP authority 与 HTTP base，datasetId 必须是认证返回的 canonical 数据集身份。因此相同附件在不同账号、不同部署或服务端重建后都不会复用。
缓存文件以附件端点的 SHA-256 命名，mtime 作为 LRU 访问时间并受容量配额约束；同一附件并发下载
单飞，内容先写入唯一 `.part`，完成后原子发布，失败或退出会清理残片。下载在 HTTP 前按
`Attachment.size` 与一个文件条目同时做原子预留，已有文件与所有并发预留之和不得超过任一配额；响应长度缺失时仍按
实际分块计数，声明或实际字节与附件元数据不一致都不发布缓存。图片、视频、语音、普通附件、
TXT/Markdown 预览和群文件共用这一路径。旧的进程级媒体目录不迁移或回退读取。

Desktop 默认对整个 `media_e2` 根共享 512 MiB 和 4096 个最终文件，Android 对整个 app cache 媒体根使用相同总预算；
身份 namespace 只隔离命中，不各自复制配额。单文件超过协议上限直接拒绝；正在被图片解码、播放器、预览或
外部打开流程持有的最终文件拥有显式租约，LRU 不能删除；Desktop 在同步移交给系统后立即释放，文本预览
由当前 Ready 状态独占，并在主线程替换、dismiss 或宿主销毁时释放。Android `FileProvider` 的读取接管是异步的，
因此普通附件保留最近一次成功打开的租约，直到下一次打开请求或控制器销毁；文本预览页保留到下一次外部打开或页面销毁。
Android 的附件、缩略图、语音和视频跨类别与身份目录共享同一并发字节与条目账本；
已原子发布的 Android 缓存跨页面和进程重启复用，页面退出只取消未完成传输并释放播放器，不删除最终文件。最终文件仅由容量 LRU、系统 `cacheDir` 回收或显式数据清理删除；缓存命中或下载发布会在同一容量锁内原子取得文件租约，视频、语音和缩略图消费者释放前 LRU 必须跳过该文件。两端的字节与条目预留在失败、取消和 owner 替换时都必须释放；启动残留 `.part` 在扫描最终文件前删除，不得绕过条目上限。

Desktop 资源固定 owner uid 与 datasetId，但 access token 由对应 `UserSession` 在每次 HTTP 请求时提供：同账号
重连后的 access 轮换立即生效，uid 变化、dataset 替换或资源关闭则退役旧资源。Android 使用平台缓存与播放器，但
同样以 deployment fingerprint + datasetId + uid 派生不透明命名空间，并遵守相同附件身份、精确大小和原子容量规则。
画廊视频遵守同一路径：缓存未命中时先完成带当前 Bearer 的全文件下载、精确大小校验和原子发布，随后
播放器只读取完整的本地文件。缓存命中时播放不使用服务器带宽，seek、暂停和恢复也不产生网络
请求。页面切换、账号/dataset 退役或会话关闭会取消自己的下载等待者并释放播放器；已经合法下载到
终端的字节不能靠服务端撤权远程收回，撤权只阻止新的下载或重新下载，本地缓存按账号与设备生命周期
治理。

## 8. 安全

- 附件 URL 只能解析 TeamTalk 文件端点。
- 文本附件类型以 MIME 为主；只有空或通用二进制 MIME 才按最终扩展名识别，严格 UTF-8 解码并
  拒绝二进制控制字符，下载与预览使用同一认证会话缓存。
- 链接点击交给平台安全打开策略；Android 与 Desktop 均仅允许无凭据的 `http/https` 和合法
  `mailto`，普通消息与回复正文遵守同一策略；不可信 mention uid 不能直接拼入页面路由。
- 外链图片和原始 HTML 默认不渲染。
- 卡片 action、联系人名片侧信道和编辑/撤回必须由服务端重新校验；mention 也必须属于当前会话成员。
- 超长 Markdown 应限制渲染成本，同时保留原始消息可查看。
