# Android 客户端

## 1. 导航模型

Android 使用单 Activity、Compose NavHost 和系统返回栈。一级栏目由底部导航承载；资料、搜索、群
详情和任务通常进入全屏目的页。它不复用 Desktop 的 Window、右侧检查器或三栏布局。

```text
MainActivity
  └── Home（会话 / 通讯录 / 文档 / 设置）
       └── NavHost destinations
            ├── Chat
            ├── UserProfile
            ├── GroupDetail
            ├── GroupFiles
            ├── DocumentWorkspace（首页 / 空间文档树 / 编辑器）
            ├── CreateGroup
            └── Search / Security / Devices …
```

## 2. 平台体验

- 列表项最小 72dp，头像 48dp，TopAppBar 56dp。
- 长按打开上下文菜单；没有 hover 和右键概念。
- 系统返回按 NavHost/弹层顺序退出。
- 输入法动作与 Enter 行为必须适配软键盘；不能照搬 Desktop 快捷键。
- 权限、通知、媒体选择和后台生命周期由 Android 层处理。
- edge-to-edge 模式下，共享二级页头只在 Android 壳显式消费顶部安全区；Desktop 原生标题栏
  不重复增加该留白。修改密码、编辑资料、设备、黑名单等页面遵守同一页头规则。
- 编辑资料中的头像使用系统 Photo Picker；应用把 provider URI 有界复制到当前账号私有临时目录，按
  EXIF 方向归一后自动居中裁成不超过 512×512 的真实方形 PNG，再经认证 `FileRepository` 上传。本批
  不提供可拖动取景框，处理、上传、替换、清除和错误状态均在当前页面明确展示。
  每次处理前只检查当前账号 `outgoing-avatar` 目录的前 128 个候选，保留最新 8 个、单次至多删除 32 个
  超过 24 小时或超出保留量的非活动临时文件，不遍历其他媒体缓存。

### 消息通知的当前范围

已登录会话从 LocalCache 会话投影观察新增未读。Activity 进入后台且连接已认证时，非静音会话的新消息
生成标准系统通知；回到前台、会话已读/静音或退出账号时清理。每次认证完成的首个快照只建基线，
不把冷启动或离线同步的旧未读批量弹成新通知。通知只展示会话名和未读数量。

点击通知等待当前账号与导航就绪，再通过已有聊天入口定位；账号、部署或 dataset 不匹配的目标丢弃。
Android 13 及以上登录后自动申请一次通知权限，拒绝不影响登录或收发，也不会每次重连重复请求；
以后需要提醒时可从系统应用设置开启。

这段收集不依赖后台 Compose 重组，但不含前台保活服务、厂商 Push 或系统回收后的唤醒。
**进程存活不等于系统允许后台联网**；后台网络受限或进程被回收后，可能仍须重新打开应用同步，
不能据此承诺可靠的移动后台投递。目标设备的后台、锁屏与回收验证属于 CLIENT-07 后续工作。

## 3. 与 Desktop 共享的内容

- ViewModel、Repository 与 LocalCache 数据流。
- 主题语义色、字阶、间距和头像规则。
- 消息 body renderer 的领域解释。
- 通讯录、搜索结果、资料动作等可复用内容片段。

共享组件通过参数适配尺寸与动作，不能读取 Desktop 导航对象或创建 Window。

## 4. 通讯录与搜索

Android 通讯录同样先区分组织架构与好友；组织层级和部门成员语义与 Desktop 一致，资料仍用 Android
全屏页面承载。好友列表可以保留右侧字母索引，因为竖向触控快速跳转在长列表中有价值。全局搜索从
TopAppBar 入口进入全屏结果页，分类和数据源与 Desktop 一致。

消息结果进入带可选 `targetSeq` 的 Chat 目的页。恢复返回栈后仍由 `chatId + serverSeq` 重建同一定位
意图；实际有界历史加载、精确滚动、高亮和撤回/不可用反馈全部复用共享聊天状态机。

发送消息进入终态失败后，消息行只展示跨端稳定的公开原因，不回显传输异常正文。用户始终可以经二次
确认显式丢弃；只有稳定失败码证明服务端未接受时，才可进入原 Markdown 内容编辑并以全新的
`clientMsgId` 原子替换重发。超时、断线、ACK 异常等未知结果不提供新身份重发；两种恢复都复用共享
持久 outbox，进程重建后不把服务端已确认消息误删或重复发送。

组织目录同样先展示持久投影，并区分本地读取中、尚未缓存、权威空目录与仍可离线浏览的 stale
nonempty；未知空不能显示成“尚未配置”，旧非空投影也不能作为权限权威。在线刷新及认证恢复对账复用
共享层的二进制 `OrganizationRpc`，不由 Android 壳另写 HTTP 目录客户端。

好友列表与 Desktop 共用 Presence 展示语义：头像右下只为明确 ONLINE 的好友显示 10dp 绿色圆点和
“在线”辅助语义；UNKNOWN、OFFLINE 或缺少状态均不显示，不把断线后的未知状态写成离线。组织成员和
资料页当前不增加同类指示。

添加好友、建群和好友申请的产品归属不因平台变化：添加好友从资料发起，建群从明确成员上下文
发起，好友申请是通讯录固定入口。建群页在本地命令恢复完成前不允许覆盖操作；断网、超时或进程
重建后恢复同一 operationId 与规范载荷，直接重试不会重复建群。

## 5. 聊天与媒体

消息语义与 Desktop 一致，但媒体播放使用 Android 平台能力：图片加载、Media3/MediaPlayer、系统
文件选择和下载目录。客户端仍遵守统一附件相对路径，不直接信任消息中的任意 URL。

- 首次进入同步最近一页；上滑到消息顶部会继续加载更早历史，顶部同时保留显式“加载更早消息”入口。
- 每次安装只生成一个持久设备标识，手工登录、注册和自动登录共用；已有持久凭据时冷启动先进入本地
  会话，会话首页在非在线状态显示连接提示。普通断网、服务维护和连接数限制继续展示缓存；这些
  可重试 AUTH 结果只撤销连接 Bearer，不卸载本地会话。只有权威认证失效才清理会话并返回登录页。
- Android 业务根只以 `AuthState.session` 中仍 active 的会话进入工作区；本地会话标记与资源引用若有
  任何不一致都回退到登录/加载表面，不对可空 session 强制解引用，也不重建半套业务 owner。
- TCP 建立后先协商协议版本，再发送 AUTH 凭据。兼容但 minor 较旧时，
  `ProtocolUpgradeBanner` 在 NavHost 上方持续提示更新，当前工作区仍可使用。
- 已知客户端低于服务器最低 minor、major 不兼容或支持窗口无交集时，停止本次连接的重连。
  `AndroidAuthenticationSurface.PROTOCOL_UPGRADE`
  优先于本地会话和加载态，不挂载业务 NavHost；不可取消的弹窗提供说明和“退出应用”，
  不承诺自动下载或安装。低于最低 minor 或客户端 major 落后的拒绝按
  `deployment + 精确 major/minor ID` 持久保存，同一被淘汰版本离线重启也不得重开工作区；新 minor
  不继承旧版本拒绝。服务器自身过旧只阻断当前壳，管理员升级服务器后重新启动即可再次协商，凭据保留。
- 冷启动保留本地优先：离线时不能预测服务器刚提高的最低版本；此前未知的要求在恢复连接收到明确
  拒绝后生效。普通断网、超时和 DNS 错误只触发网络恢复，不能误判成强制升级。
- `TeamTalkApp` 在初始化持久所有者前检查客户端自身的协议 major。安装较高 major 的客户端会重置
  当前应用数据并重新登录；同 major 的 minor 升级走 schema 迁移，保留草稿、outbox 和身份。
  运行中收到服务器的版本拒绝本身不会触发这次重置。发行字符串仅用于显示，不能参与兼容比较。

输入器支持多行、富文本、`@` 和附件。触屏空间不足时可以调整工具栏或使用 bottom sheet，但发送
出的 Markdown/Attachment 契约必须一致。

只有当前聊天 route 处于 `RESUMED`、连接已认证且编辑器发生真实正文变化时才尝试发送 TYPING；成功
准入后执行 2 秒 leading throttle，失败或离线不推进窗口。收到当前会话内其他成员的信号后，在输入器
上方显示“显示名 正在输入…”，每次续期 3 秒；断线、对方新消息进入当前投影、离开或销毁聊天都会
清除该提示。该状态不写 SavedState、SQLite 或消息历史。

受保护媒体在进入会话 UI 时捕获不可变的 `canonical TCP+HTTP deployment + datasetId + owner uid`，并绑定该 `UserSession` 的原子凭据
读取器。上传、下载、缩略图、语音/视频播放、文本预览和群文件必须显式传递同一个会话值，不能
读取全局“当前 token”。同一 uid 重连轮换 access 后，下一个 HTTP 请求立即读取新 access，缓存命名
空间保持稳定；`UserSession` 后来承载另一 uid 或服务端确认 replacement dataset 时，旧媒体任务按
owner epoch 失败关闭，绝不能借用新账号或新 dataset token。TCP authority、HTTP base、datasetId 或账号任一变化都会切换缓存目录；页面退出只取消自己的未完成任务并释放播放器，不能删除已原子发布缓存。完整缓存跨页面与进程重启复用，由容量 LRU、系统 `cacheDir` 或显式数据清理回收；进程级语音播放器由
`Application` 统一关闭。进程级语音播放器把下载请求、已发布播放器和界面状态收口到同一个世代
所有权门：页面或认证会话先关闭发布资格，再取消下载并释放当前播放器；较晚完成的准备任务只能
释放自己的未发布播放器。页面停止播放必须匹配创建请求的认证媒体会话对象，不能只比较稳定的账号
缓存命名空间；因此同一 uid 重新登录或页面转场时，旧页面的迟到销毁不会停止新会话播放器。自然播放
结束同样会原子清空当前 URL、状态并释放原生播放器。
进入语音模式时即预先申请麦克风权限，授权后第一次真正长按直接录音。权限结果本身不得
续接被系统弹窗取消的指针手势，指针取消、离页或应用进入后台都必须释放并丢弃录音资源。
录音启动、发送收尾和丢弃路径都先尝试 `stop`、`release` 与残片删除；普通的原生状态异常可以降级，
协程取消和非 `Exception` 缺陷必须在清理完成后以原对象传播。
Media3 播放器的创建、`prepare` 与 listener 安装按事务移交所有权；任一步失败都会释放已创建播放器，
组合销毁也会在移除 listener 失败后继续尝试 `release`。
画廊视频先通过认证媒体会话完整下载、核对附件声明大小并原子发布到账号隔离缓存，再把本地文件 URI
交给 Media3。播放器不持有服务端 URL、Bearer 或 HTTP DataSource；拖动、暂停和恢复都只读取本地文件。
缓存命中校验、下载发布与文件租约在同一容量锁内完成，播放器、语音播放器和缩略图解码都在租约
释放前阻止 LRU 驱逐；视频由一个组合协程按“下载/命中 → 创建播放器 → release → 释放租约”单向拥有。
页面退出、快速翻页或 owner 退役会取消尚未完成的下载，迟到结果不能创建播放器。
附件读取同样从原子发布直接交接到租约；IO dispatcher 返回途中若调用方取消，已创建租约由交接 helper
自动关闭，不会成为永久 pin。系统 `FileProvider` 打开异步接管文件，控制器只保留最近一次成功打开的附件租约；
下一次打开请求在下载预留前先释放旧租约，页面销毁也会释放，避免旧大文件阻塞新文件下载。

附件、图片缩略图、语音和视频下载统一在 `Dispatchers.IO` 内执行，调用者即使来自 Compose 主线程
也不能在主线程触发连接或阻塞读取。缓存命名空间同时绑定 canonical deployment fingerprint、canonical datasetId 和 uid，服务端重建后不得复用旧 dataset 媒体。下载前按 `Attachment.size` 在整个 app cache 媒体根共享的 512 MiB 与 4096 个最终文件上限中，
同时原子预留字节和一个文件条目；不同身份目录及附件、缩略图、语音、视频并发合计都不能超配额，零字节附件也不能无界占用 inode。首次真实预留前清理所有合法媒体目录中上次进程的无主 `.part`；
缺失 `Content-Length` 时按实际字节计数，伪造长度、实际
越界、取消或 owner 替换都只清理 `.part` 并释放预留。文本附件“使用其他应用打开”失败时在当前
页面展示明确错误；已经退休的认证 owner 不得收到迟到反馈。

文件卡首次出现时先同步发布 `Checking`，随后只在文件 worker 上读取系统 `cacheDir`、探测对应缓存文件，
并回到 UI owner 收敛为 `Idle` 或 `Done`。同一路径只保留一个探测；点击下载/打开会使旧探测代际失效，
控制器关闭后迟到结果也不能发布。小文件自动下载必须等待探测明确返回 `Idle`，`Checking` 和缓存命中的
`Done` 都不能触网；用户点击打开时，缓存租约探测和系统文件打开同样不占用 Compose Main。视频播放器和
文本附件预览也先在 IO 解析缓存根，再进入原有下载、租约和解析链。Android 的全量媒体 LRU 与遗留 partial
扫描原本就只在 IO 下载预留路径首次执行，因此不为平台形式对称而复制 Desktop 的启动期全量候选资源图。

小米真机的临时 debug StrictMode 探针验收在每个目标操作前清空日志：进入聊天文件卡和打开已加载文档中的图片
分别产生 0 条主线程磁盘读写违规。文档草稿恢复现在还会保留持久层明确返回的“当前 owner 无草稿”事实，
空工作区后续同步不再重复执行 SharedPreferences 删除；同批制品冷启动进入文档首页也产生 0 条主线程
磁盘读写违规。这个结果只覆盖上述入口，不代表 Android 全应用已经清零；双端草稿 owner 的完整资源交接
和其他尚未逐入口量测的平台工作继续由 Roadmap `CLIENT-06` 跟踪。

会话名作为导航查询参数传递时由构造端编码、CHAT 目的页边界解码，空格、字面量 `+`、百分号和
非 ASCII 名称不能相互混淆。回复卡片优先显示服务端从同一会话目标消息重建的发送者快照；兼容旧
消息时只按 `replyToSenderUid` 调用当前会话绑定的发送者解析器，无法解析才显示短 UID，不能借用
其他会话状态。

## 6. 群共享文件

群详情中的“共享文件”进入独立全屏页面。文件选择使用 Storage Access Framework，上传成功后再发布到
当前群目录；打开文件复用带 Bearer token 的下载控制器和系统 Intent。目录与版本语义和 Desktop
一致，但导航、返回和文件选择保持 Android 原生行为。

## 7. 企业文档

底部导航提供独立“文档”入口，不从群详情进入。文档页面使用自己的标题栏，不再叠加 Home 的通用
TopAppBar。Android 明确采用单文档前台模式，手机和平板都按“文档首页 → 空间文档树 → 编辑器”逐层
显示，不展示 Desktop 多标签栏；系统返回按“编辑器 → 空间文档树 → 文档首页 → 会话一级入口”消费。
文档树与 Desktop 共享“标题打开正文、展开按钮只控制子文档”的语义，不显示文件夹大图标或文件夹卡片；行内容保持紧凑，同时使用约 44dp 高的触控命中区。编辑器顶部只保留空间标题栏的一个
“返回文档树”入口。返回或打开/新建另一篇前会同步捕获编辑器最后一拍正文：干净文档直接关闭并回到文档树，未保存文档和新建草稿必须
确认放弃；取消后正文继续保留。
保存进行中请求离开、切换或关闭时，确认框不会提前消失；关闭结果明确提示正在保存，只有草稿取消标记
持久化并移除旧编辑器后才执行目标导航。服务器已删除但本机仍有修改的页面显示醒目状态和“另存为新
文档”，旧页面的保存、历史、移动和删除入口不再可用。
从底部导航离开“文档”也执行同一保护，取消确认时继续停留在文档页；首页最近索引不能绕过隐藏草稿，
异步打开已有文档后默认进入预览，需要修改时再显式切换编辑；新建草稿仍直接进入编辑。首页索引、编辑、预览、版本历史、空间权限与冲突语义
和 Desktop 相同，包括干净文档的紧凑“移动到…”目标树以及保存冲突的两种显式恢复选择，但不复制多栏、标签、窗口尺寸或桌面快捷键。

可编辑且非预览状态的文档提供系统图片/文件选择器和显式“粘贴”入口。二进制剪贴板从首个
`ClipData.Item` 的 `uri` 或 `intent.data` 取得资源，与 picker 共用同一条预处理、认证上传、Markdown
占位和 sidecar 收敛链路。物理键盘 `Ctrl/Meta+V` 只在实际命中二进制资源时消费按键；剪贴板只有
普通文本时返回给聚焦编辑器执行原生粘贴。预览或只读状态不接受新资源；Android 文档拖放尚未实现。

聊天和文档的系统 picker 在启动时捕获编辑器 owner 与资源类型，并把这个一次性 token 按
canonical deployment + dataset + uid 绑定在 `rememberSaveable` 中。取消也会消费 token；同一
Activity 内仍使用启动时的 owner，Activity 重建后则只在当前编辑器 owner 与原 owner 相同时
接收返回结果，不把迟到资源交给另一篇文档或另一个会话。provider 的 MIME、显示名和大小在
`Dispatchers.IO` 解析，然后才进入共用的有界复制和上传链路。小米真机已完成系统 picker
选图、上传、保存、强停重开和预览验收。debug 构建可在 picker 保持打开时执行下面的定向夹具；它只重建
`MainActivity`，不会断开宿主机或设备网络：

```bash
adb shell am broadcast \
  -a com.virjar.tk.android.DEBUG_RECREATE_ACTIVITY \
  -n com.virjar.tk.android/com.virjar.tk.DebugActivityRecreationReceiver
```

当前这台小米设备及其当前系统构建已确认同一进程内产生新的 Activity 实例，但图片 picker 和文件 picker
返回时都在 `ActivityThread.deliverResultsIfNeeded` 抛出空指针，本次没有观察到应用 callback 或资源导入。
应用内 token、callback 先于 owner 重绑、不同 owner 拒绝和 exactly-once 已由确定性测试覆盖；真实平台门禁
仍需在不会丢失 ActivityResult 的 AOSP/emulator 或另一台设备补证，不能把状态机单测写成真机通过。

断网进入文档页时先显示本机草稿以及 SQLite 中最近一次成功收敛的空间、首页和已读取树分支；已缓存
干净正文可立即打开，开始修改后交给独立草稿续写层。已确认为空的分支有持久 marker，从未读取的分支
和正文则显示“尚未缓存”，不会用空内容冒充可用。网络、超时和 5xx 保留现有页面；403 或根分支 404
退出整个空间，子分支 404 只移除对应文档及本地已知子树，并保留未保存正文为本地孤儿。工作台打开后
恢复连接会刷新空间、首页、当前树和正文。当前仍没有 document Notify 或全空间预取，另一设备修改依赖
进入、导航、手动刷新或重连 RPC 收敛。

Android 页面壳统一从 `AppDataState` 的 session 内 FIFO 反馈队列租用错误与已审阅通知，
Snackbar 正常展示完成后才确认删除；Activity 重建会释放未完成租约，新壳可接续同一条反馈。
因此删除失败等文档错误必须对用户可见，不能只停留在状态层。

## 8. 生命周期

- Activity 重建不能重建用户身份或丢失持久化 token；文档未保存正文按 canonical deployment + dataset + uid 写入应用私有、禁止
  备份的逐记录存储，不写入 SavedState/Bundle，也不聚合成一个大 JSON。`onStop` 只同步捕获 Compose 编辑器最后一拍，随后向
  `Application` 持有的单写队列投递可等待的 durability barrier，不能在主线程等待磁盘；该队列跨
  Activity 重建继续排空，并提供幂等异步关闭。小 manifest 原子指向内容寻址记录，读取保留
  `ABSENT / AVAILABLE / RETRYABLE` 三态；AtomicFile 的 `.bak` 恢复、单记录损坏隔离和上一份完整快照都不能被超时误判为不存在。进程重建后恢复原
  space/document/parent-document/instance 与编辑世代；主动退出、切换账号、保存成功或明确放弃时先使旧写入
  世代失效。明确放弃还必须先写独立取消 tombstone，再移除标签或创建 outbox；主动退出使用 owner 删除封印阻止迟到写复活。
  认证失效仅撤销凭据并返回登录页，保留 canonical deployment + dataset + uid 隔离的未保存工作供同一账号重新认证；其他账号不会继承该 store。
- `onStop` 返回前只保证最后一拍已经进入进程队列，不宣称已经落盘；只有异步 barrier 成功完成才是 durability
  边界。队列饱和或上一队列失败时，最后一拍进入固定的单个合并接管槽，仍由进程单写者在前序任务后
  落盘，Main 不等待、不编码也不写磁盘；接管 barrier 会继续报告被替换队列的失败。正常编辑期间持续
  合并写入以缩小窗口；若系统在 barrier 完成前直接终止
  进程，下次启动恢复的是上一份完整快照，而不是伪造“最后一拍必然持久”。主线程不得为此同步等待磁盘。
- ClientSession 属于用户层，不应绑定单个页面。
- 账号 SQLite 在首次、非正常关闭、损坏回调或周期到期后执行完整性检查。确认损坏时只隔离当前
  deployment + dataset + uid 数据库族并创建干净投影库；保留的隔离库不自动删除，因为其中可能还有
  outbox 或草稿。具体恢复边界见[LocalCache](../03-architecture/client-and-sdk.md#6-localcache)。
- 页面点击、路由 `LaunchedEffect`、系统权限与 ActivityResult 回调都必须经过当前
  `AppDataState` 准入。suspend 业务在会话作用域中运行，Activity/route 作用域只等待；退役后的文件
  选择、上传完成或旧 Home 点击不得再发送消息、构造 ChatViewModel 或导航。
- logout 和 auth-expired 同时经 holder 当前 owner 与 AuthController 期望 `ClientSession` 两层引用恒等校验，
  旧 Activity 的迟到回调不能退出新 Activity 已安装的账号。
- 上传和下载遇到 401 时会携带请求实际使用的 Bearer 回到精确会话的认证控制器；最终校验若发现
  access 已轮换则丢弃迟到结果。403 与其他 HTTP 状态不会触发退出，错误也不会包含服务端响应体。
- 切后台可能影响通知和媒体，但普通暂停不等于登出。
- `AUTH_FAILED` 必须按类型处理：权威凭据撤销清持久登录并返回登录页；可重试结果只撤销连接 Bearer、
  保留本地会话；协议拒绝保留账号工作并进入强制升级表面。安装跨 major 新版本的数据重置由启动所有者负责，普通网络断开只触发后台重连。
- 认证会话上报 Android/系统/ABI/厂商型号、客户端版本、构建 identity 与 git commit。业务状态机持续向
  typed sink 提交页面、系统与办公动作事件，但页面停留、一般前后台和 `ACTION` 仅在 `DIAGNOSTIC`
  策略准入时进入批次；`BASELINE` 只保留允许的故障、提示、关键连接状态和失败媒体事件。隐私边界统一
  遵守[可观测性](../07-operations/observability.md)，Android 页面不得自行上传正文、路径或动态 ID。
- 遥测是 best-effort 旁路：spool 或 crash pending 初始化失败时，只关闭当前会话遥测并留下固定本机诊断；
  若仅跨 namespace 维护能力不可用，则保留当前会话遥测，只跳过旧 namespace 回收。已持久化账号仍须
  先建立本地会话并进入主界面；网络连接和服务端同步随后异步收敛。
- Android 遥测根固定使用 app-private `filesDir`；external/SAF、网络盘、FUSE 或语义未知 provider 不受支持。

## 9. 验证

本地 JVM 测试覆盖共享逻辑，Android 特有行为使用真机/模拟器、ADB 和 uiautomator2 验证。涉及
服务端或跨客户端的业务结果仍以真实部署验收为准。
