# Desktop 交互容器模型

> 这份文档约束共享业务屏幕在 Desktop 上“放在哪里”，用于阻止早期 Android 全屏页面继续直接复用为桌面大页面。

## 1. 容器选择

| 用户意图 | Desktop 容器 | 当前功能 | 约束 |
|---|---|---|---|
| 快速查看一个对象 | 居中模态弹窗 | 用户资料 | 不改变右栏上下文；ESC 关闭；动作不超过 3 个 |
| 查看当前会话的上下文 | 聊天右侧覆盖式检查器 | 群详情、邀请成员、邀请链接 | 与当前会话绑定；覆盖而不替换聊天；可形成短栈；不弹系统窗口 |
| 跨业务域查找内容 | 主窗口右栏工作区 | 全局搜索 | 输入位于应用顶栏；结果按消息/联系人/文件/服务分类 |
| 完成一段输入或选择任务 | 独立任务窗口 | 建群、转发、编辑资料、修改密码、设备、黑名单、好友申请 | 窗口级关闭；根页无返回箭头；内部下一层才返回 |
| 确认危险或不可逆动作 | 小型确认对话框 | 删除好友、离群、撤销邀请 | 只解释影响并给确认/取消，不承载完整业务页 |
| 移动端页面导航 | Android NavHost 全屏页 | 同一批共享业务能力 | 保留 56dp 居中触控页头和系统返回，不反向约束 Desktop |

## 2. Desktop 排版规则

1. 页头使用 48dp、标题左对齐；Android 页头使用 56dp、标题居中。
2. macOS 主窗口与任务窗口都使用融合式标题栏，原生窗口按钮和应用 Surface 属于同一视觉层。
3. 对象摘要采用“头像 + 名称 + 元信息”的横向结构；只有 Android 全屏资料页可以使用纵向居中 hero。
4. 桌面危险动作使用低强调文字按钮；不得为了填满宽度把低频动作做成通栏大按钮。
5. 任务窗口的表单和列表允许滚动，模态对象预览本身不滚动；信息超出时应升级为检查器或任务窗口。
6. 聊天检查器宽 400dp，从右侧滑入且不参与聊天布局测量；打开/关闭不得重建聊天页或改变消息滚动位置。

## 3. 本轮迁移结果

- 用户资料：由右栏全屏页改为 400dp 模态弹窗，联系人、消息 @、群成员、全局搜索入口统一。
- 子窗口：根页移除返回箭头；macOS 标题栏融合；保存/完成后的关闭回调仍保留。
- 共享页头：通过平台密度令牌区分 Desktop 左对齐 48dp 与 Android 居中 56dp。
- 群详情：由替换聊天内容改为 400dp 右侧覆盖式检查器；群聊头部使用明确的齿轮入口，根页提供关闭按钮。
- 创建群组：Desktop 使用横向任务表单；Android 保留纵向触控引导。

后续新增共享页面必须先在本表选择容器；如果底层数据能力尚未提供，保留明确空态或缺口说明，不用移动端页面或演示数据填充。
