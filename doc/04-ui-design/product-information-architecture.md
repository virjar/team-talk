# 产品信息架构

> 本文约束“功能应该出现在哪里”。组件怎么画见 `components.md`，底层缺口见 `placeholders.md`。

## 1. 全局壳层

TeamTalk 是多内容类型的协作客户端，不把产品结构等同于“会话列表 + 若干按钮”。

### Desktop

```
┌──────────────────────────────────────────────────────────────┐
│ macOS 窗口按钮  TeamTalk      全局搜索（⌘K）          在线状态 │
├────┬──────────────┬──────────────────────────────────────────┤
│主导│ 当前栏目列表   │ 当前对象内容 / 全局搜索结果 / 资料面板       │
│航  │              │                                          │
└────┴──────────────┴──────────────────────────────────────────┘
```

- macOS 保留原生窗口按钮，应用 Surface 延伸到标题区域；不再出现独立灰色系统标题条。
- 顶部只承载**应用级能力**：产品身份、全局搜索、连接状态。
- 左栏是一级导航；中栏是当前一级栏目中的集合；右栏是选中对象的内容或详情。
- 搜索结果占用右栏，搜索输入始终留在全局顶栏，避免重复输入框。

### Android

- 底部导航仍是一级导航。
- TopAppBar 仅保留当前栏目标题和全局搜索入口。
- 搜索进入全屏结果页；数据源、分类和缺失能力提示与 Desktop 共用。

## 2. 动作归属

| 能力 | 正确入口 | 不再出现的位置 | 原因 |
|------|----------|----------------|------|
| 全局搜索 | Desktop 顶栏 / Android TopAppBar | 会话、通讯录中栏标题 | 搜索跨消息、用户、文件、服务，不属于单一栏目 |
| 添加好友 | 全局搜索用户结果 → 用户资料 → 添加好友 | 会话栏“加人”图标 | 先识别用户，再建立关系，流程可解释 |
| 发起群聊 | 好友资料页“发起群聊”（该好友默认选中） | 会话/通讯录标题栏 | 建群需要明确初始成员和上下文 |
| 好友申请 | 通讯录固定“新的朋友”行 | 通讯录标题栏图标 | 这是通讯录内容，不是全局命令；无红点时也必须可发现 |
| 邀请群成员 | 群详情 | 用户资料与全局标题栏 | 只在已有群上下文中成立 |
| 编辑资料/安全/设备 | 我的/设置 | 全局顶栏 | 账号域能力 |

## 3. 全局搜索模型

分类固定为：`全部 / 消息 / 联系人 / 文件 / 服务`。分类入口稳定，数据能力可渐进补齐。

| 分类 | 数据源 | 当前状态 | 结果动作 |
|------|--------|----------|----------|
| 会话（全部内） | 本地会话缓存 | ✅ | 打开会话 |
| 消息 | 服务端消息搜索 | ✅ | 打开消息所属会话；精确定位待补 |
| 联系人 | 本地好友 + 服务端用户搜索 | ✅ | 打开用户资料；非好友可申请 |
| 文件 | 附件元数据索引 | 🔴 | 当前显示明确缺口，不伪造结果 |
| 服务 | 机器人/应用/工作台注册表 | 🔴 | 当前显示明确缺口，不伪造结果 |

搜索输入防抖 280ms；本地结果立即计算，远端消息和用户并行查询。Desktop 快捷键为
`Cmd/Ctrl+K`。

## 4. 缺失能力的 UI 规则

1. 信息架构已确定、底层未实现：保留分类或页面，并展示“缺少什么能力”，不放可误触的假按钮。
2. 没有真实数据：显示空态，不使用演示数据伪装成功。
3. 权限与索引能力必须由服务端完成；客户端不能通过遍历历史消息模拟越权搜索。
4. 能力接入后只替换结果数据源，不重新发明导航入口。

## 5. 页面空态

- 会话：选择会话，或使用顶部搜索查找内容。
- 通讯录：选择联系人，查看资料并从资料页发消息/建群。
- 设置：提示在左栏管理资料、安全、设备和外观；不得继续显示“选择会话”。
- 搜索无结果：区分“确实无结果”和“底层能力未接入”。
